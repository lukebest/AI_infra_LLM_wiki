## 📖 阅读任务（约 90-120 分钟，3 篇核心 + 1 篇选读）

### 必读论文（按从易到难的顺序）

#### 📄 论文 1：Balfour & Dally, "Design Tradeoffs for Tiled CMP On-Chip Networks"
**ICS 2006** | 25 min

这是 4 篇里**最结构化**的一篇，专门讲"片上多核处理器"（CMP）的 NoC 权衡。先读它建立坐标系。

**核心论点**：
- Tiled CMP = 同构核 + 2D Mesh + 维序路由 + Wormhole
- 这种"通用模板" 为什么至今仍是 ARM Mali/Intel Mesh 的范式？
- 关键论据：**面积/功耗约束下**，2D Mesh 的成本最低、扩展性最好

**读完要带走的洞察**：
1. CMP 的 NoC 必须满足 4 个约束：**面积、功耗、延迟、吞吐**
2. 4 种候选拓扑（Mesh / Torus / Ring / Fat-Tree）在 CMP 上的取舍表：

| 拓扑 | 面积 | 单跳延迟 | 二分带宽 | 适合规模 |
|------|------|---------|---------|---------|
| Ring | ✅ 极小 | ❌ O(N) | ❌ 差 | ≤16 核 |
| Mesh | ✅ 小 | ✅ O(√N) | ✅ 好 | 16-256 核 |
| Torus | 中（多了环绕链路）| ✅ O(√N/2) | ✅ 更好 | 64-256 核 |
| Fat-Tree | ❌ 大（高基数）| ✅ O(log N) | ✅ 最好 | ≥64 核 |

3. 为什么**Intel Xeon Phi**（KNC/KNL）最后选了 Mesh/Torus 而不是 Fat-Tree？
   - 因为 Mesh/Torus 用**低基数路由器**（5-port），面积/功耗小
   - Fat-Tree 需要**高基数路由器**（几十端口），片上实现代价过高
   - 这是"方法论四层"的取舍：拓扑 → 路由器微架构 → 链路带宽 → 物理实现

#### 📄 论文 2：Dally & Towles, "Route Packets, Not Wires: On-Chip Interconnection Networks"
**DAC 2001** | 30 min

这是 NoC 领域的**奠基论文**。很短（6 页），但每个字都值得读 3 遍。

**核心论点**：
- "**未来片上互连将像网络一样设计，而不是像总线一样设计**"
- 给出 5 个 NoC 关键设计决策：拓扑、路由、流控、路由器微架构、NI
- 这一框架直接成为后续 25 年所有 NoC 论文的骨架（也包括这本书）

**读完要带走的洞察**：
1. **"Packets not Wires" 的三层含义**：
   - 从总线 → 网络：从单共享介质到多跳交换
   - 从电路交换 → 报文交换：从专用连接到统计复用
   - 从硬件协议栈 → 通用协议栈：从厂商私有到标准接口
2. **5 个设计决策的相互约束**：
   - 选 Mesh → 路由只能 DOR 或 Turn Model
   - 选 Wormhole → 必须用 VC 打破死锁
   - 选 5-port 路由器 → 微架构只能用简单 iSLIP，不能用复杂 PIM
3. **为什么这篇 2001 年的论文"现在还不过时"？**
   - 因为 NoC 设计空间**没变**：拓扑/路由/流控/微架构/NI 这 5 个问题至今没人能绕过
   - 真正变的是：工艺、规模、约束（如今天 90 万 PE 的 WSE）

#### 📄 论文 3：Hoskote et al., "A 5GHz Mesh Interconnect for a Teraflops Processor"
**IEEE Micro 2007** | 35 min

这是 Intel **80 核 Teraflops 处理器（Polaris）** 的 NoC 设计。**教科书级的工程实录**。

**核心设计参数**：

| 参数 | 值 | 含义 |
|------|---|------|
| 拓扑 | 10×8 2D Mesh | 80 个 tile 排成矩形 |
| tile 类型 | 同构（CPU + Router）| 一致性 + 计算 |
| 路由器 | 5-port，虚跨步（virtual bypass） | 省面积，省能耗 |
| 时钟 | 5 GHz，2 GHz mesh | mesh 比 tile 慢，半频 |
| 流控 | Wormhole + 2 VC | 死锁避免 |
| 单跳延迟 | 2 拍 router + 1 拍 link | ≈ 1.2 ns @ 5GHz |

**读完要带走的洞察**：
1. **Mesh 是 CMP 的"最低公分母"**：80 核的 Intel、Tilera、AMD 都用它
2. **为什么是 5-port router？** 因为 4 个邻居 + 1 个本地核 = 5 端口，这是 Mesh 拓扑下的最少端口数
3. **虚跨步（virtual bypass）**：当包下一跳是"直走"时，**绕过**整个路由器流水线，节省 2-3 拍延迟
   - 这是 Day 18 学过的"路由器优化"的工程实现
4. **频率为什么是 mesh 2 GHz / tile 5 GHz？** 因为 wire delay 限制 + mesh 全局同步难 → 半频设计
5. **80 核为什么不做 Fat-Tree？** 因为 Fat-Tree 需要 64+ 端口的路由器，**片上做不出来**
   - 这就是 Balfour & Dally 2006 的预判对了

#### 📄 选读论文 4：Cerebras WSE 公开技术报告 / WhitePaper
**Cerebras Inc. 2019-2024** | 30 min

WSE 论文不像传统学术论文那么"结构化"，但每篇都泄露了**关键设计决策**。**重点读 3 个问题**：

1. **拓扑**：WSE-2 的 2D Mesh 是 7×12 = 84 个 core die × 每个 die 复制 → WSE-3 是 ~949×949 Mesh，**每个 PE 有 4 个邻居 + 1 个本地 memory port = 5 端口**（与 Polaris 80 核一致的"低基数"原则！）
2. **路由**：DOR（XY 路由）的某种变体，配合**自适应路由**应对 hot-spot（推测）
3. **流控**：极简 wormhole + 1-2 VC（与 Polaris 一致）

**关键对比表（读完要补完）**：

| 系统 | 规模 | 拓扑 | Router | 频率 | 流控 |
|------|------|------|--------|------|------|
| Intel Polaris 2007 | 80 核 | 10×8 Mesh | 5-port | 5/2 GHz | Wormhole+VC |
| Tilera TILE-Gx | 72 核 | 8×9 Mesh | 5-port | 1.2 GHz | Wormhole+VC |
| Cerebras WSE-3 | **900K PE** | ~949×949 Mesh | 5-port? | ~1 GHz? | Wormhole? |
| IBM BlueGene/Q | 1M 核 | 5D Torus | 11-port | ? | 多种 |

**惊人发现**：Intel Polaris (2007) 和 Cerebras WSE-3 (2024) **竟然用同样的拓扑选择**！为什么 17 年后这个选择仍然最优？
- 答案：**5-port 路由器 + Mesh 是片上可制造性 + 通用性的"甜点"**

## 🔑 核心概念（必须掌握）

### 1. 论文"读三层"框架

每篇 NoC 论文，按这 3 层读：

```
┌─────────────────────────────────────────────┐
│ 第 1 层：贡献 (Contribution)                  │  ← 一句话说清楚
│  "本文解决了 X 问题，用 Y 方法，得到 Z 结果"     │
├─────────────────────────────────────────────┤
│ 第 2 层：方法 (Method)                       │  ← 5 个设计决策
│  拓扑 / 路由 / 流控 / 微架构 / NI 怎么选        │
├─────────────────────────────────────────────┤
│ 第 3 层：约束 (Constraints)                  │  ← 为什么是这个方法
│  面积 / 功耗 / 延迟 / 吞吐 / 可制造性           │
└─────────────────────────────────────────────┘
```

**应用示例**（论文 3 Polaris）：

- 第 1 层：本文设计一个 80 核 Teraflops 处理器的 5GHz Mesh 互连。
- 第 2 层：Mesh 拓扑 + DOR 路由 + Wormhole 流控 + 5-port 路由器 + tile-level NI。
- 第 3 层：**面积约束**（片上，5-port 优于高基数）+ **功耗约束**（mesh hop 短）+ **延迟约束**（bypass 直走优化）+ **吞吐约束**（DOR 简单但够用）。

**WSE 视角**：
按此框架，WSE 论文的 3 层应该是：
- 第 1 层：在单晶圆上集成 90 万 PE 的片上互连
- 第 2 层：2D Mesh + DOR + Wormhole + 5-port 路由器 + 显式消息 NI
- 第 3 层：**可制造性约束**（chip yield，与今天的良率挑战有关）+ **确定性流量**（LLM 推理）+ **极简功耗**

### 2. CMP NoC 的 4 大设计原则（Balfour & Dally 2006 提出）

| 原则 | 含义 | 为什么 |
|------|------|--------|
| **原则 1：低基数路由器** | router 端口数 ≤ 8 | 端口数 =² 交叉开关面积 |
| **原则 2：规则拓扑** | Mesh/Torus 而不是 irregular | 良率友好 + 路由简单 |
| **原则 3：维度对齐** | k-ary n-cube | DOR 直接可用 |
| **原则 4：流控极简** | Wormhole + 2-4 VC | 不浪费片上 buffer |

**所有 25 年 NoC 芯片都遵守这 4 个原则**：
- Intel Polaris、Tilera、Samsung MPSoC、AMD Zen CCX、ARM Mali
- **Cerebras WSE 也是**（基于 WSE 公开材料的推测）

**WSE 的"违反"和"遵守"**：
- ✅ 遵守：低基数（5-port）、规则（2D Mesh）、维度对齐（XY）、流控极简
- ❌ 看上去"违反"：规模 ~949×949，规模上比传统 CMP 大 3-4 个数量级
- 解释：**"规模大 ≠ 违反原则"**——只要每个 PE 仍是低基数路由器，整体规模可以"叠加"

### 3. "5 GHz Mesh" 的工程意义

**Hoskote 2007** 为什么强调 5 GHz？

| 频率 | 单跳延迟 | 性能 |
|------|---------|------|
| 1 GHz | 1 ns/级 | 慢 |
| 2 GHz | 0.5 ns/级 | 中 |
| **5 GHz** | **0.2 ns/级** | 快（80 核 Teraflops 必需）|

**Mesh 频率为什么不能到 5 GHz？**（Polaris 实测：tile 5 GHz，mesh 2 GHz）
- 原因 1：长 wire delay（mesh 链路跨多个 tile，wire RC 大）
- 原因 2：跨 tile 同步难（clock skew、jitter）
- 解决：**mesh 半频 + 流水化**（每个 hop 2 拍 = 1ns @ 2 GHz）

**WSE 视角**：
WSE 工作频率 ~1 GHz（推测），单跳延迟 ~1-2 ns。**比 Polaris 慢 5 倍**。但因为：
- Mesh 半径更长（~1000 hops vs 10 hops）
- Packet 更大（几百 byte vs 64-128 byte）
- 调度器**编译时静态规划**流量

→ **总延迟未必比 Polaris 大**

### 4. Mesh vs Fat-Tree 的"设计哲学分歧"

```
Mesh/NoC 哲学：
"长度匹配" — 让长消息穿越短路径
- 拓扑规则 → 路由简单 → DOR/最短路径
- 路由器低基数 → 面积小，可堆叠
- 适用：规模 ≤ 几百万，强约束于面积/功耗

Fat-Tree/HPC 哲学：
"带宽最大" — 让所有消息都能并行
- 拓扑不规则 → 路由复杂 → Up*/Down* 或 adaptive
- 路由器高基数 → 面积大，集中化
- 适用：规模 ≤ 几万，强约束于全带宽
```

| 维度 | Mesh (NoC) | Fat-Tree (HPC/DC) |
|------|-----------|------------------|
| 路由器基数 | 低（5 port）| 高（64-port 常见）|
| 单跳延迟 | 短 | 短 |
| 长距离延迟 | O(√N) | O(log N) |
| 二分带宽 | 中 | **最高**（严格无阻塞）|
| 累计带宽 | 受 √N 限制 | 受端口数限制 |
| 面积 / 功耗 | ✅ 小 | ❌ 大 |
| 适合规模 | 数千 PE | 数十万节点 |

**Cerebras WSE 的"哲学"**：
- 表面上用 Mesh（NoC 哲学）
- 实际**用规模换带宽密度**——90 万 PE × 每条 Mesh 链路 ~1 Tb/s = 总带宽超过 InfiniBand Fat-Tree
- **"Mesh 哲学 + 规模优势"** 是 WSE 的真正创新

### 5. NoC 论文"何时是真贡献，何时是新瓶旧酒"

读完 4 篇论文后，建立一个**评审 checklist**：

```
□ 这篇论文是否真的提出新拓扑？
  ├─ 没有 → 大概率是路由器微架构优化
  └─ 有 → 检查：是否能与已有拓扑被图同构？

□ 新流控机制？
  ├─ 没有 → 大概率是路由算法改进
  └─ 有 → 检查：是否真的解决了 deadlock/HoL/Starvation？

□ 新路由器微架构？
  ├─ 没有 → 大概率是 NI 或协议
  └─ 有 → 检查：是否进入"流水级延迟 < 1"的极限？

□ 新 NI 设计？
  ├─ 没有 → 大概率是评测/benchmark
  └─ 有 → 检查：是否解决了 End-to-End 真正关心的？

□ 真实硅实现 vs 仿真？
  ├─ 仿真 → 检查 BookSim 准确性 + 工作负载
  └─ 真实硅 → 看测得频率、面积、功耗
```

**真正有影响力的 NoC 论文**通常具备**至少 2 项新东西** + **真实测量**。

## 🧪 练习题（约 90-120 分钟）

### 基础题（论文消化）

**Q1（Dally 2001 的核心论断）**：用一句话总结 "Route Packets, Not Wires" 的核心论点。

> **参考答案**：
> 未来的片上互连应当按**网络**（多跳交换 + 报文交换）而非**总线**（共享介质 + 专用连接）方式设计，
> 并按 5 个标准设计维度（拓扑/路由/流控/微架构/NI）统一分析。

**Q2（Polaris 5-port 的来源）**：为什么 Polaris 用 5-port 路由器，而不是 4 或 6？

> **参考答案**：
> - 4 端口 = 3 邻居 + 1 本地，不够（Mesh 内部节点要 4 个邻居）
> - 5 端口 = 4 邻居 + 1 本地，**刚好是 Mesh 内部节点的最小可行端口数**
> - 6 端口 = 多一个本地端口（用于双核 tile），增加成本但收益小
> - **端口数² = crossbar 交叉开关面积**，故 5 是甜点

**Q3（Balfour & Dally 拓扑选择表）**：N=64 的处理器，最适合的拓扑是？N=8 呢？N=2048 呢？

> **参考答案**：
> - N=8：**Ring**（最简单，O(N) 延迟够用）
> - N=64：**Mesh（8×8）或 Torus（4×4×4）**（低基数 + 短延迟）
> - N=2048：**Fat-Tree**（Mesh 直径 ~45 太长，Torus 仍有 ~16 跳；Fat-Tree 延迟 O(log N)≈11）

**Q4（论文对比表）**：填完下面这个 4 论文对比表：

| 论文 | 拓扑 | 路由器端口 | 流控 | 主要贡献 |
|------|------|-----------|------|---------|
| Dally 2001 | 通用框架 | 通用 | 通用 | "把 NoC 设计空间定义出来" |
| Balfour 2006 | Mesh 主导 | 5-port | Wormhole | "片上 CMP 的拓扑取舍论" |
| Hoskote 2007 | 10×8 Mesh | **5-port** | Wormhole+VC | "5 GHz 实测 + bypass" |
| Cerebras WSE | **949×949 Mesh** | 推测 5 | 推测 Wormhole | "巨型单芯片 NoC 的工程化" |

> 答案**关键观察**：18 年后，WSE 还用 5-port Mesh——这就是**方法论的胜利**

### 进阶题（与方法论综合）

**Q5（用 21 天方法论分析 WSE）**：基于 19 天的学习，写出 WSE PE 的 5 个设计层推测：

```
WSE PE / Network（用 21 天方法论分析）：

1. 拓扑：949×949 2D Mesh（推测）
   - 原则 Balfour & Dally #2（规则拓扑）→ Mesh
   - 端口数限制 → 不能 Fat-Tree
2. 路由：DOR (XY) + 自适应路由（推测）
   - Mesh 上的 DOR 是基础（Day 11）
   - 自适应用于 hot-spot（Day 12）
3. 流控：Wormhole + 2-4 VC（推测）
   - 标准 CMP NoC 做法（Balfour 原则 #4）
4. 路由器微架构：5-port + bypass（推测）
   - 同 Polaris（Day 17-18）
5. NI：极简 Send/Recv + 端到端可靠（Day 19）
   - 无 DMA、无 TCP、无 OS
```

**Q6（设计哲学对比）**：InfiniBand Fat-Tree 和 NoC Mesh 本质上是**两种设计哲学**。请各举 3 个"典型应用场景"：

> **参考答案**：
> **Fat-Tree 适用**：
> 1. 大模型训练的 AllReduce（带宽敏感，需要全对全）
> 2. HPC 模拟中的全对全通信（如 N-body）
> 3. 云数据中心的 East-West 流量（VM 间）
> 
> **Mesh/NoC 适用**：
> 1. CMP 内的 cache 一致性流量（短消息、多对一）
> 2. WSE 上的 LLM 推理（结构化流量，编译时已知）
> 3. Mobile SoC 上的 IP 核互连（面积/功耗敏感）

**Q7（Cerebras WSE 的"创新本质"）**：从方法论看，WSE 不是"NoC 创新"而是"规模创新"。为什么这个区分重要？

> **参考答案**：
> - WSE 没有发明新拓扑、新路由、新流控
> - 它让 **Mesh × 90万规模**首次可行
> - 这背后的工程创新是：**chip yield** + **wafer-scale interconnect** + **memory fabric**
> - 这意味着**真正的 NoC 研究空间已经"挖完了"**——剩下的不是新理论，是工程化
> - **对你研究的意义**：你做 NPU 内 NoC 的优化，参考 Balfour/Hoskote 就够了；要做"创新"，得在**编程模型 + 编译器 + 算法映射**这些**非互连层**找突破口

> **参考答案**：
