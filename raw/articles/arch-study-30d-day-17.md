## 🔑 核心概念（必须掌握）

### 1. DRAM 访问延迟分解（最关键！）

DRAM 一次访问由四个阶段组成，每个阶段都是 ns 级别的"硬墙"：

```
┌─────────────────────────────────────────────────────────┐
│  DRAM 访问时序 (以 DDR5-6400 为例)                          │
├─────────────────────────────────────────────────────────┤
│  t_RCD  (RAS-to-CAS Delay):   ~14.0 ns    行选通→列选通    │
│  t_RP   (Row Precharge):      ~14.0 ns    关闭当前行       │
│  t_CAS  (CAS Latency / tCL):  ~16.0 ns    列选通→数据出来   │
│  t_BURST (4-cycle burst):      5.0 ns     数据突发传输     │
└─────────────────────────────────────────────────────────┘
```

**三种访问场景**：

| 场景 | 时序 | 延迟 |
|------|------|------|
| 首次访问某行（空 buffer） | `t_RP + t_RCD + t_CAS + t_Burst` | ~49 ns |
| 同 row buffer 命中 | `t_CAS + t_Burst` | ~21 ns |
| 跨行访问（需要 precharge） | `t_RP + t_RCD + t_CAS + t_Burst` | ~49 ns |

**关键洞察**：从 80ns（首次访问）到 21ns（buffer 命中），差距近 4×。**Row Buffer 命中率是 DRAM 性能的第一命门**。

### 2. 带宽公式

```
单通道带宽 = 数据速率 (MT/s) × 总线宽度 (bit) ÷ 8

DDR5-6400:  6400 × 64  ÷ 8 =  51.2 GB/s  (单通道)
DDR5-6400 双通道:                102.4 GB/s
HBM3 单 stack (1024-bit @ 6.4 GT/s):  819.2 GB/s
HBM3e 单 stack (1024-bit @ 9.2 GT/s): 1177.6 GB/s
H100 整机 5 个 HBM3 stack:            3350 GB/s
```

### 3. Bank/Channel 并行性

现代 DRAM 通过**三种并行**提升带宽：

```
┌─ Channel 并行 (粗粒度) ────────────────────────────────┐
│  DDR5 双通道 = 102.4 GB/s (vs 单通道 51.2 GB/s)        │
│  H100 有 12 个 HBM channel                            │
└──────────────────────────────────────────────────────┘
┌─ Rank 并行 (中等粒度) ────────────────────────────────┐
│  多个 die 共享 channel，但独立操作                       │
│  2-rank 交错访问可隐藏 precharge 延迟                    │
└──────────────────────────────────────────────────────┘
┌─ Bank 并行 (细粒度) ───────────────────────────────────┐
│  每个 rank 有 16-32 个 bank                            │
│  不同 bank 可以独立打开不同 row                         │
│  通过 bank interleaving 提高并发性                     │
└──────────────────────────────────────────────────────┘
```

**为什么并行这么重要？**
- 单 bank 的 t_RCD + t_CAS ≈ 30 ns，每次只能取 64 字节
- 等效吞吐 = 64 B / 30 ns = 2.1 GB/s per bank
- 需要 16 个 bank 并行才能达到 32 GB/s 通道利用率

### 4. 内存墙 (Memory Wall)

**Hennessy & Patterson (1989) 提出：DRAM 访问延迟每年仅降 1.05×，而 CPU 频率每年提升 1.5×**——这是著名的"内存墙"。

```
算力增长:    ~1.5× / 年 (2000 年前)
内存延迟增长: ~1.05× / 年
→ 算力与内存差距每年扩大 1.4×

到了 2020s:
- NVIDIA H100 FP16 算力: 1979 TFLOPS
- H100 HBM3 带宽: 3350 GB/s
- 算力/带宽 = 590 FLOPS/byte
→ 任何算力强度 < 590 FLOPS/byte 的工作负载 = 带宽受限
```

**AI 训练的算力强度是多少？**

| 任务 | 算力强度 (FLOPS/byte) | 受限情况 |
|------|----------------------|---------|
| GPT-3 175B 推理 (单 token) | ~590 | 临界 |
| GPT-3 175B 训练 (forward) | ~30 | **带宽受限** |
| Stable Diffusion 推理 | ~50 | **带宽受限** |
| 简单 CNN 推理 | ~5 | **严重带宽受限** |

→ **AI 几乎所有场景都是带宽受限，不是算力受限**——这就是 H100 必须堆 80GB HBM3 的根本原因。

### 5. WSE 的极端方案：分布式 SRAM

WSE-3 的反直觉设计：
- **没有 DRAM**，全部内存 = 900K PE × 48KB SRAM = ~40 GB 片上 SRAM
- **总带宽 = 21 PB/s = 21,000,000 GB/s**
- **单 PE 内部带宽密度**：约 50 GB/s/PE（估算）

```
对比:
GPU H100:    80 GB HBM3  +  3350 GB/s     带宽/容量 = 42 GB/s per GB
WSE-3:       40 GB SRAM  +  21,000,000 GB/s   带宽/容量 = 525,000 GB/s per GB
                                                                 ↑ 
                                                       WSE 比 GPU 高 12,500×
```

**这就是 WSE 在 AI 工作负载上数量级领先的根本原因——它用面积换带宽，绕过了内存墙。**

## 🧪 练习题（约 30-60 分钟）

### 基础题

**Q1**：计算 DDR5-6400 双通道的理论峰值带宽。
> 答：6400 MT/s × 64 bit × 2 ÷ 8 = **102.4 GB/s**

**Q2**：HBM3 单 stack 8-Hi 的带宽。HBM3 数据速率 6.4 GT/s，每 stack I/O 宽度 1024-bit。
> 答：6.4 GT/s × 1024 bit ÷ 8 = **819.2 GB/s**

**Q3**：某 LLM 推理工作负载算力强度 = 50 FLOPS/byte，需要 100 TFLOPS 算力。问至少需要多少内存带宽？DDR5-6400 双通道够不够？
> 答：所需带宽 = 100 TFLOPS ÷ 50 FLOPS/byte = **2 TB/s**
> DDR5-6400 双通道只有 102.4 GB/s，**相差约 20 倍**。所以 LLM 推理必须用 HBM 或片上 SRAM。

**Q4**：用 Roofline 模型分析 H100 在 FP16 Tensor Core 下的性能瓶颈点（Ridge Point）。
> 算力：1979 TFLOPS；带宽：3350 GB/s
> Ridge Point = 1979 / 3350 ≈ **590 FLOPS/byte**
> 当 AI 工作负载算力强度 < 590 → 带宽受限；> 590 → 算力受限

### 进阶题

**Q5**：WSE-3 用 21 PB/s 片上 SRAM 取代 HBM，这划算吗？用面积/成本/性能三个维度分析。

| 维度 | HBM3 方案 | WSE-3 方案 |
|------|----------|-----------|
| 内存容量 | 80 GB (5 stack) | ~40 GB (片上 SRAM) |
| 带宽 | 3.35 TB/s | 21,000 TB/s |
| 带宽/容量 | 42 GB/s per GB | 525,000 GB/s per GB |
| 单 GB 成本 | ~$10 | ~$500 (估算，按晶圆面积折算) |
| 适用工作负载 | 大模型 (>40GB 显存) | 任何能塞进 ~40GB 的模型 |

**关键洞察**：WSE 的 SRAM 比 HBM 贵 ~50×/GB，但**带宽密度高 12,500×**。对于带宽受限的 AI 工作负载，这笔买卖**非常划算**——AI 推理/训练中，瓶颈在带宽，不在容量。

### 思考题（与 WSE 研究关联）

**Q6**：如果你正在设计 NPU 核，你会选择 HBM 接口还是纯 SRAM？这取决于什么因素？

**回答思路**：
- **HBM 接口**：适合通用加速器（要兼容多种模型大小，能跑 GPT-4 这种 >40GB 的模型）
- **纯 SRAM**：适合专用加速器（模型固定，如 Llama-3 70B 可拆分到多 WSE 联合推理）
- **Luke 自己的方向**：可以探索"近 SRAM 模型"——模型参数常驻片上 SRAM，绕过 HBM

**Q7**：DRAM 的 Row Buffer 命中率和 Cache 命中率有什么本质区别？为什么前者提升空间更小？

**回答思路**：
- Cache 命中率：通过精巧替换算法（LRU, ARC, ...) 可达 95%+
- Row Buffer 命中率：受数据访问模式限制，AI 训练中 GEMM 访问模式相对友好（~70%），但推理中 KV cache 访问模式差（~30-50%）
- 本质区别：Cache 可由硬件调度；Row Buffer 由访问顺序决定，硬件只能"被动等待"

## 🔗 与 WSE / NoC / NPU 研究的关联

### 1. WSE 的内存哲学：把内存墙彻底"绕过"

```
通用 GPU 路径:        CPU/GPU Core → Cache → Memory Controller → HBM → DRAM cells
                      带宽: 几百 GB/s, 延迟: 几百 ns, 容量: 几十 GB

WSE 路径:             PE → 片上 48KB SRAM (500ns 范围) → Mesh NoC → 其他 PE SRAM
                      带宽: 21 PB/s, 延迟: <100 ns, 容量: 40 GB
```

**WSE 的革命性不是 PE 多，而是"消灭了内存墙"**——AI 工作负载从此不再受限于 HBM 带宽。

### 2. WSE 的"代价"是什么？

| 代价 | 量化 |
|------|------|
| 晶圆面积 | 46,225mm² 是 H100 (814mm²) 的 57× |
| SRAM 成本 | ~40 GB SRAM ≈ 1/3 晶圆面积 |
| 良率 | 全晶圆良率挑战（已知难题，但 Cerebras 通过冗余 + route-around 解决） |
| 编程复杂度 | 必须显式管理数据布局 (CSL) |

### 3. 抛给 Luke 的研究问题

1. **NoC 设计的"内存感知"问题**：
   - 传统 NoC 假设内存是远端统一节点
   - WSE NoC 假设每个节点都是"近端内存"
   - 你的 NoC 研究是否考虑了"分布式内存"拓扑的特殊性？

2. **NPU 核设计的"内存-算力配比"**：
   - TPU v1: 256K MAC + 4MB SRAM（SRAM/MAC = 16 bytes/MAC）
   - WSE PE: 1 MAC + 48KB SRAM（SRAM/MAC = 48K bytes/MAC，**比 TPU 高 3000×**）
   - 你的 NPU 核研究：这个配比应该是多少？取决于工作负载

3. **核内同步与内存模型**：
   - WSE 单时钟域天然消除内存一致性需求
   - 通用 NPU 必须面对多核一致性（Day 18 内容）
