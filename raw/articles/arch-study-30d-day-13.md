## 今日主题：内存层次基础 + Cache

### 🧭 为什么今天学这个？

过去五天你深入学习了处理器核心——流水线、超标量、乱序执行、分支预测、指令窗口。但再快的处理器，如果数据供不上，也是空转。

**内存墙 (Memory Wall)** 是过去 30 年体系结构最持久的挑战。CPU 性能每年提升约 55%（2005 年前），而 DRAM 延迟每年仅改善约 7%。这个不断扩大的鸿沟，正是 Cache 存在的根本原因。

今天你将建立存储层次的完整概念框架。这些知识不仅是理解现代 CPU 的关键，更是后续理解 WSE "为什么不用传统 Cache 层次"的重要对比基础。

## 🔑 核心概念（必须掌握）

### 1. 局部性原理（复习 + 量化）

```
时间局部性 (Temporal Locality)：
  最近访问过的数据，很可能在短期内再次被访问
  → 留在 Cache 里

空间局部性 (Spacial Locality)：
  地址相近的数据，很可能在近期被访问
  → 按 Cache Line（块）预取

量化经验值：
  - 典型程序的空间局部性：一个 64B 的 Cache Line 中，
    平均有 4-8 次连续访问
  - 时间局部性：90% 的执行时间花在 10% 的代码上（循环热点）
```

### 2. 存储层次结构

```
┌──────────────────────────────────────────────────┐
│  Register File    │  < 1 ns    │  ~1 KB          │  ← Day 12 学过
├────────────────────┼────────────┼─────────────────┤
│  L1 Cache          │  ~1-2 ns   │  32-64 KB       │  ← 今天重点
├────────────────────┼────────────┼─────────────────┤
│  L2 Cache          │  ~3-10 ns  │  256 KB - 1 MB  │
├────────────────────┼────────────┼─────────────────┤
│  L3 / LLC Cache    │  ~10-20 ns │  8-64 MB        │
├────────────────────┼────────────┼─────────────────┤
│  DRAM (主存)        │  ~80-100 ns│  16-256 GB      │  ← Day 17 深入
├────────────────────┼────────────┼─────────────────┤
│  SSD / NVMe        │  ~10-100 μs│  TB 级           │  ← Day 20
├────────────────────┼────────────┼─────────────────┤
│  HDD / 网络         │  ~10 ms+   │  ∞               │
└──────────────────────────────────────────────────┘

核心规律：每上一层，容量约 1000×，延迟约 10×
```

### 3. Cache 映射方式（必须理解的三种方式）

给定一个内存地址，它应该放在 Cache 的哪个位置？

#### (a) 直接映射 (Direct-Mapped)

```
每个内存地址只能映射到 Cache 中的唯一一行

地址分解：
  ┌─────────┬──────────┬──────────┐
  │  Tag    │  Index   │  Offset  │
  └─────────┴──────────┴──────────┘

Cache 查找：
  用 Index 定位到 Cache 的某一行
  比较 Tag → 命中 or Miss

优点：简单、快速、硬件成本低
缺点：Conflict Miss 多！多个地址映射到同一行会互相驱逐

示例：4KB Direct-Mapped Cache, 64B Line → 64 行
  地址 0x0000, 0x1000, 0x2000 都映射到 Index 0 → 冲突！
```

#### (b) 组相联 (Set-Associative)

```
每个内存地址可映射到一组内的任意一行（N-way）

地址分解（与直接映射相同）：
  ┌─────────┬──────────┬──────────┐
  │  Tag    │  Index   │  Offset  │
  └─────────┴──────────┴──────────┘

Cache 结构（以 4-way 为例）：
  Index  ┌─────┬─────┬─────┬─────┐
    0    │ Way0│ Way1│ Way2│ Way3│  ← 4 路并行比较 Tag
    1    │     │     │     │     │
    ...  │     │     │     │     │
         └─────┴─────┴─────┴─────┘

优点：显著减少 Conflict Miss
缺点：N 个比较器 + N:1 MUX，功耗和面积增大

经验值：
  L1: 通常 8-way（平衡延迟和命中率）
  L2: 通常 16-way
  L3: 通常 12-16-way
```

#### (c) 全相联 (Fully Associative)

```
内存地址可放在 Cache 中的任意位置

地址分解：
  ┌──────────────────────┬──────────┐
  │        Tag           │  Offset  │
  └──────────────────────┴──────────┘
  （没有 Index 字段——所有行都要比较）

优点：Conflict Miss = 0（只要有空闲行就不会冲突）
缺点：比较器数量 = Cache 行数，成本极高

适用场景：TLB（通常 64-128 项，全相联），小容量高速缓存
```

### 4. Cache 写策略

```
              写命中 (Write Hit) 时：
              ┌─────────────────────────────┐
              │  Write-Through (写直达)       │ → 同时写 Cache 和下层
              │    优点：一致性好              │
              │    缺点：每次写都访问下层       │
              ├─────────────────────────────┤
              │  Write-Back (写回)            │ → 只写 Cache，标记 dirty
              │    优点：减少下层访问带宽       │
              │    缺点：一致性复杂            │
              └─────────────────────────────┘

              写不命中 (Write Miss) 时：
              ┌─────────────────────────────┐
              │  Write-Allocate (写分配)      │ → 把块调入 Cache，再写
              │    通常配合 Write-Back 使用    │
              ├─────────────────────────────┤
              │  No-Write-Allocate (写不分配)  │ → 直接写下层，不调入 Cache
              │    通常配合 Write-Through 使用 │
              └─────────────────────────────┘

典型组合：
  L1 Data Cache: Write-Back + Write-Allocate（最常见）
  L1 Inst Cache: 只读，不存在写问题
```

### 5. Cache Miss 的 3C 模型（经典！）

```
Mark Hill 的 3C 模型将 Cache Miss 分为三类：

  ┌────────────────────────────────────────────────────────────┐
  │  Compulsory (强制性 Miss)                                   │
  │  首次访问某块，Cache 中从未有过                              │
  │  也叫 Cold Miss / Cold-Start Miss                           │
  │  → 解决：预取 (Prefetching)                                  │
  ├────────────────────────────────────────────────────────────┤
  │  Capacity (容量性 Miss)                                     │
  │  Cache 容量不够，之前调入的块被替换出去，现在又要用           │
  │  → 解决：增大 Cache                                          │
  ├────────────────────────────────────────────────────────────┤
  │  Conflict (冲突性 Miss)                                     │
  │  Cache 容量够，但多个地址映射到同一行，互相替换               │
  │  → 解决：增加相联度                                          │
  └────────────────────────────────────────────────────────────┘

后来加入第 4 类（4C 模型）：
  ┌────────────────────────────────────────────────────────────┐
  │  Coherence (一致性 Miss)                                    │
  │  由于其他处理器的写入导致本地 Cache 块被无效化               │
  │  → 多核系统独有（Day 18 会深入）                             │
  └────────────────────────────────────────────────────────────┘

关键洞察：
  - 全相联 Cache 没有 Conflict Miss（但有 Capacity Miss）
  - 增大 Cache 可消除 Capacity Miss（但不能消除 Conflict Miss）
  - Compulsory Miss 是不可消除的（除非预取）
```

### 6. Cache 性能公式（AMAT 的前置知识）

```
Cache Miss Rate = Miss 数 / 总访问数
Cache Hit Rate = 1 - Miss Rate

平均访问时间（单层 Cache）：
  AMAT = Hit Time + Miss Rate × Miss Penalty

  Hit Time:    Cache 命中时的访问延迟（如 L1: 1-2 cycles）
  Miss Rate:   不命中的比例
  Miss Penalty: 不命中时去下层取数据所需的额外延迟

多层扩展：
  AMAT = L1_HitTime 
       + L1_MissRate × (L2_HitTime 
       + L2_MissRate × (L3_HitTime 
       + L3_MissRate × DRAM_AccessTime))

（Day 14 会深入 AMAT 的优化）
```

## 🧪 练习题（约 30-60 分钟）

### 基础题

**Q1**：一个直接映射 Cache，容量 4KB，Cache Line 大小 32B。
- 有多少行？
- 地址 0x0A7C 的 Index 和 Offset 是多少？（假设 32 位地址）

> 答：
> - 行数 = 4096 / 32 = 128 行
> - Offset 位数 = log₂(32) = 5 bits
> - Index 位数 = log₂(128) = 7 bits
> - Tag 位数 = 32 - 5 - 7 = 20 bits
> - 地址 0x0A7C = 0000 1010 0111 1100（二进制）
> - Offset = 低 5 位 = 11100 = 28
> - Index = 接下来 7 位 = 0100111 = 39（从右数第 6-12 位）
> - 实际计算：0x0A7C / 32 = 0x53E（块号），0x53E mod 128 = 62
> - 校验：0x53E = 1342, 1342 mod 128 = 1342 - 10×128 = 62
> - 所以 Index = 62, Offset = 0x0A7C mod 32 = 28

**Q2**：给定以下访问序列（字节地址）：0x0000, 0x0040, 0x0000, 0x0080, 0x0000, 0x00C0, 0x0000
在直接映射 Cache（4 行，每行 64B）上，计算命中率和各类型 Miss。

> 答：
> Cache 行大小 64B，4 行
> 地址 → 块号 → Index：
> 0x0000 → 块 0 → Index 0 → Miss (Compulsory)
> 0x0040 → 块 1 → Index 1 → Miss (Compulsory)
> 0x0000 → 块 0 → Index 0 → Miss (Compulsory)？不对，块 0 还在 Cache 中
>   实际上：块 0 在 Index 0，没被替换过 → Hit！
> 0x0080 → 块 2 → Index 2 → Miss (Compulsory)
> 0x0000 → 块 0 → Index 0 → Hit！
> 0x00C0 → 块 3 → Index 3 → Miss (Compulsory)
> 0x0000 → 块 0 → Index 0 → Hit！
>
> 总访问 7 次，命中 3 次，Miss 4 次
> 命中率 = 3/7 ≈ 42.9%
> 所有 Miss 都是 Compulsory（首次访问），没有 Conflict 或 Capacity Miss

### 进阶题

**Q3**：如果上述 Cache 改为 2-way 组相联（2 组，每路 64B），访问序列不变，命中率变为多少？

> 答：
> 2-way 组相联，4 行总共 → 2 组，每组 2 路
> 地址 → 块号 → Index（1 bit）：
> 0x0000 → 块 0 → Index 0 → Miss (C)，放入 Set 0 Way 0
> 0x0040 → 块 1 → Index 1 → Miss (C)，放入 Set 1 Way 0
> 0x0000 → 块 0 → Index 0 → Hit
> 0x0080 → 块 2 → Index 0 → Miss (C)，放入 Set 0 Way 1
> 0x0000 → 块 0 → Index 0 → Hit
> 0x00C0 → 块 3 → Index 1 → Miss (C)，放入 Set 1 Way 1
> 0x0000 → 块 0 → Index 0 → Hit
>
> 命中率 = 3/7 ≈ 42.9%（相同）
> 因为这个例子中所有 Miss 都是 Compulsory，增加相联度不能减少首次访问的 Miss。
> 但如果访问序列中存在 Conflict（如交替访问块 0 和块 4，都映射到 Index 0），组相联就能显著减少 Miss。

### 思考题（与 WSE 研究关联）

**Q4**：Cerebras WSE-3 的每个 PE 只有约 48-50 KB 本地 SRAM，没有传统 Cache 层次。对比：
- 传统 CPU：L1 32KB + L2 1MB + L3 32MB + DRAM → 多层 AMAT
- WSE：每 PE 48KB SRAM → 单层、固定延迟

用 AMAT 公式分析：在什么情况下 WSE 的单层存储比传统 Cache 层次更有优势？什么情况下劣势？

> 提示：
> - WSE 优势：无 Miss、无不确定性延迟、可精确调度 → 适合规则数据流（矩阵乘、卷积）
> - WSE 劣势：容量小（48KB）、无自动层次管理 → 程序员必须显式管理数据移动
> - 传统 Cache 优势：对不规则访问模式有自适应性、对程序员透明
> - 传统 Cache 劣势：Miss 导致不可预测的延迟 → 对实时性和确定性有害
> - 关键对比：WSE 的"无 Cache"设计是典型的"用程序员复杂性换取硬件简单性和确定性"

## 🔗 与 WSE / NoC / NPU 研究的关联

| 维度 | 传统 CPU Cache | WSE 分布式 SRAM | GPU 共享内存 |
|------|---------------|-----------------|-------------|
| 层次数 | 3-4 层 (L1/L2/L3/DRAM) | 1 层 (本地 SRAM) | 2-3 层 (Shared/L1/L2/HBM) |
| 管理方式 | 硬件自动 | 软件显式 (CSL/SpaDA) | 硬件 + 软件混合 |
| Miss 处理 | 硬件自动从下层取 | 不存在（编程模型保证数据就绪） | 硬件从 Global Memory 取 |
| 延迟确定性 | 低（Miss 导致 10-200× 延迟） | 高（固定周期访问） | 中等 |
| 适合的工作负载 | 通用、不规则 | 规则数据流、大规模张量运算 | 数据并行、图形计算 |

**核心洞察**：传统 Cache 是为"程序员不知道数据在哪"而设计的——它利用局部性自动管理数据。WSE 的设计哲学完全相反——**程序员（或编译器）完全知道数据在哪**，因此不需要 Cache 的自动管理，省下的面积和功耗全部用于计算和本地存储。

**与 NoC 的关联**：在传统多核中，L3 Cache 常常是共享的（最后一级缓存），核间通信通过 Cache 一致性协议（MESI）隐式完成。WSE 没有共享 Cache，所有核间通信必须**显式通过 NoC**完成。这使得 NoC 的设计变得极其关键——它不仅是通信通道，更是整个系统的数据供给骨干。
