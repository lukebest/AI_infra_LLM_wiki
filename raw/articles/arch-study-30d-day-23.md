## 🔑 核心概念（带公式）

### 1. 多线程的三种实现方式

```
┌─────────────────────────────────────────────────────────┐
│ 方式          │ 切换时机          │ 流水线利用率 │ 复杂度 │
├─────────────────────────────────────────────────────────┤
│ Fine-grained  │ 每条指令后切换    │ 高          │ 中     │
│ Coarse-grained│ 长时间 stall 切换│ 中          │ 低     │
│ SMT           │ 同时多发射多线程  │ 最高        │ 高     │
└─────────────────────────────────────────────────────────┘
```

**关键洞察**：SMT 让多个线程**共享同一套硬件资源**（寄存器堆、Cache、Functional Units），但**每个线程有独立的 PC、寄存器、ROB 项**。当一个线程 stall（Cache miss）时，另一个线程可以使用这些空闲资源。

### 2. SMT 性能公式

```
SMT_Speedup = (Σ_throughput_multithreaded) / (Σ_throughput_single_thread)

简化模型：
  IPC_total = Σ_i IPC_i  (各线程 IPC 之和)
  
  SMT 收益 ≈ 1.2-1.3× （理想 2× 几乎不可能）
```

**为什么达不到 2×？**
- 资源竞争：两个线程争抢相同的执行单元
- 缓存污染：两个线程的工作集互相干扰
- 关键路径：单线程的关键路径没变

### 3. Amdahl 定律（多核版）

```
Speedup(N) = 1 / ((1 - f_parallel) + f_parallel / N + Overhead(N))

其中：
  f_parallel = 可并行部分占比
  N = 核数
  Overhead(N) = 通信 + 同步 + 一致性开销（随 N 增长）
```

**多核扩展性的现实曲线**：

```
理想 Amdahl:  Speedup(N) → 1/(1-f_parallel)  (有限上限)

加上 Overhead(N) = c·log(N) 或 c·N^p:
  - 通信主导 (p=1):  Speedup(N) 在某个 N* 处达到峰值，然后下降
  - 一致性主导:      N* 通常在 8-32 之间
```

### 4. NUCA (Non-Uniform Cache Access)

```
传统 Cache（早期）：    均匀访问延迟（核心在中心，Cache 周围）
现代大 Cache（NUCA）：  访问延迟取决于数据位置
                      - 靠近核心的 Cache slice：~10 cycles
                      - 远的 Cache slice：~50 cycles
                      - 平均：~25 cycles
```

**为什么需要 NUCA？**
- L3 Cache 越来越大（几 MB 到几十 MB）
- 单个 slice 物理分布在芯片各处
- 访问延迟随距离增加（导线延迟主导）
- **结论**：Cache 不再是"透明"的存储层次，编程时需要考虑数据布局

### 5. 多核的"调度策略"问题

```
同一时刻，每个核运行什么？
├── Symmetric：所有核相同，OS 自由调度（最常见）
├── Asymmetric (AMP)：大核 + 小核混合（ARM big.LITTLE）
├── Dynamic：硬件根据负载调整（Intel Thread Director）
└── Spatial：核 + 任务位置感知（NUMA-aware scheduling）
```

**对你的研究的暗示**：
- WSE 900K PE 是**极度 Spatial** 的——任务放置直接影响 NoC 通信开销
- 这就是为什么 WSE 的编译器（SME）要做 placement optimization
- **你的研究方向（NoC-aware scheduling）和这个高度相关**

## 🧪 练习题（约 60 分钟）

### 基础题

**Q1：Amdahl 定律 + 通信开销**

某并行程序可并行部分占 95%。在 64 核上理想加速比是多少？如果每核通信开销为 5μs，总工作时间 100ms，加入通信后实际加速比是多少？

> **答**：
> 理想：Speedup = 1/(0.05 + 0.95/64) = 1/0.0648 = 15.4×
> 实际：串行部分 = 5ms（保持不变）
>       并行部分 = 95ms / 64 = 1.484 ms
>       加通信：并行部分 ≈ 1.484 + 5×10⁻³×64/2 = 1.484 + 0.16 = 1.644 ms
>       总时间 = 5 + 1.644 = 6.644 ms
>       Speedup = 100 / 6.644 = 15.05×
>       （通信开销很小，因为并行部分短）

**Q2：SMT 效率估算**

某超标量核单线程 IPC = 2.0。加入 SMT 后两线程联合 IPC = 3.2。
- SMT 加速比是多少？
- 资源利用率提升是多少？

> **答**：
> 加速比 = 3.2 / 2.0 = 1.6×（理想是 2×）
> 资源利用率提升 = 60%（从单线程满载到双线程 1.6×）
> 说明 60% 的硬件资源在单线程下是闲置的（SMT 利用了这部分）

### 进阶题

**Q3：多核扩展性曲线**

某 benchmark 在 N 核上的实测加速比如下：
| N | 1 | 2 | 4 | 8 | 16 | 32 | 64 |
|---|---|---|---|---|----|----|----|
| Speedup | 1.0 | 1.9 | 3.6 | 6.2 | 9.5 | 12.0 | 13.5 |

用 Amdahl 定律拟合 f_parallel 和 Overhead。

> **答**：
> 假设 Amdahl + Overhead = c·N·log(N)（通信主导）
>
> 试 N=4: 1/(1-f + f/4) - 3.6 = c·4·2 → 0.025 = 8c
> 试 N=8: 1/(1-f + f/8) - 6.2 = c·8·3 → 0.0735 = 24c
> 试 N=64: 1/(1-f + f/64) - 13.5 = c·64·6 → 0.0113 = 384c
>
> 反算：N=8 → c ≈ 0.003, N=64 → c ≈ 0.00003
> c 不固定 → 模型过于简化。
>
> 更现实的模型：**Amdahl + 一致性瓶颈**：
> f_parallel ≈ 0.97（从 N=8 数据反推：1/0.126 ≈ 7.94 vs 实测 6.2，说明有 22% 损失）
> 随 N 增长，一致性流量 O(N²) 成为瓶颈。

### 思考题（与 WSE 研究关联）

**Q4：WSE 的"扩展性悖论"**

Cerebras WSE-3 有 900K PE。在传统 CPU 上，64 核后 Amdahl + 一致性就开始饱和。
为什么 WSE 能做到 900K PE 仍保持高利用率？WSE 用了哪些"反 Amdahl"的设计？

> **答（提示方向）**：
> 1. **没有共享内存**——每 PE 私有 SRAM + NoC 消息传递，消除一致性流量（O(N²) → O(N)）
> 2. **没有 Cache**——单时钟域访问，无 coherence miss
> 3. **同步开销极低**——单时钟域 + 短链路（Day 19 学过）
> 4. **数据流编程模型**——SME 编译器显式做 placement，把通信局部化
> 5. **片上距离短**——21 PB/s 带宽 vs H100 的 3 TB/s（7000×），掩盖了通信延迟
>
> **代价**：编程模型复杂（不是通用 CPU），不灵活

## 🔗 与 WSE/NoC 研究的关联

### 1. 多核扩展性 → WSE 的设计哲学

```
传统多核的扩展性瓶颈（教科书）：
  - Amdahl: 串行部分限制上限
  - 通信: O(N) 或 O(N²) 一致性流量
  - 一致性: 目录/MESI 的复杂状态机
  - 内存墙: 多核争抢带宽

WSE 的解决方案：
  - 消除串行部分：所有 PE 都能跑独立任务
  - 消除一致性：消息传递 + 私有内存
  - 消除内存墙：所有数据 on-chip SRAM（43 GB）
  - 用空间换问题：芯片面积翻 100 倍，但消除了 90% 的复杂度
```

### 2. SMT → 你的"核内同步"研究

SMT 共享**执行单元**和**Cache**，但**不共享寄存器堆**（除了很小的交换区）。这和你研究的"核内同步"是什么关系？

**思考**：
- 同一核的两个硬件线程 = 几乎零延迟的"通信通道"
- 但同步原语仍然需要（thread 间的信号）
- 你的研究方向：**把同步做成 SMT 级别的硬件原语？**
  - 比如：硬件 barrier 指令，<1 ns 完成（vs 软件 50-100 ns）
  - 比如：硬件 mailbox，两个 thread 直接交换数据
  - 这就是 WSE 的"单时钟域同步"思路

### 3. NUCA → WSE 的分布式 SRAM

传统多核的 NUCA：
- L3 分布在芯片各处（banks）
- 访问延迟不均匀：远端 slice 50 ns vs 近端 10 ns
- OS / 编译器要做 placement 优化

WSE 的分布式 SRAM：
- 每个 PE 有 48-50 KB 私有 SRAM
- 通过 NoC 访问其他 PE 的 SRAM
- 距离 = NoC 跳数（每跳 ~1 ns）
- **WSE 是 NUCA 的极端形式**——延迟完全取决于 NoC 拓扑和路由

**对你的 NoC 研究的启示**：
- 评估 NoC 时，**不能只看平均延迟**，要看延迟分布
- 短消息（1-2 跳）vs 长消息（100 跳）的优化策略不同
- 路由算法对延迟分布的影响比对平均值的影响更大

### 4. 多核设计空间 → 你设计 NPU 核时的决策树

```
你的 NPU 核如何选择？
├── 单核 vs 多核？
│   ├── 任务并行度高？ → 多核
│   └── 数据并行度高？ → SIMD/SIMT（看 Day 24）
├── 核间互连？
│   ├── 简单 → 总线 / Ring
│   ├── 中等 → Crossbar（≤16 核）
│   └── 复杂 → Mesh / NoC（>16 核）
├── 缓存策略？
│   ├── 私有 L1 + 共享 L2/L3（传统）
│   ├── 全私有 + 消息传递（WSE）
│   └── Scratchpad + DMA（DSP/嵌入式）
└── 一致性？
    ├── 需要共享编程模型 → MESI/目录
    └── 专用编程模型 → 不需要
```
