## 今日主题：间接网络 — Clos、Fat-Tree 与数据中心互连的脊梁

### 🧭 为什么今天学这个？

前 6 天我们都在**直连网络（Direct Network）**上思考：节点既是终端又是路由器，每个 PE 都有度数限制。但现代数据中心、HPC 集群、长距离电信网络几乎都用**间接网络（Indirect Network）**：终端节点和交换节点分离，交换节点专门负责转发。这种拓扑的"无阻塞特性"和"成本可扩展性"是直连网络难以企及的。今天你会掌握间接网络设计的核心数学——**Clos 定理**和**Fat-Tree 的代价函数**。

## 🔑 核心概念（必须掌握）

### 1. 直连网络 vs 间接网络

| 维度 | 直连网络（Mesh/Torus） | 间接网络（Clos/Fat-Tree） |
|------|------------------------|---------------------------|
| 节点角色 | 每个节点既是终端又是路由器 | 终端只发收，交换节点专职转发 |
| 度数限制 | 受 pin count 限制（≤ 8 常见） | 终端节点度低（通常 1），交换节点度高 |
| 扩展性 | 受节点度限制 | 通过交换节点级联可线性扩展 |
| 典型规模 | 数十到数千 PE | 数千到数十万服务器 |
| 代价 | 链路数 = O(N·d/2) | 交换节点数 ≈ O(N·log N) |
| 代表 | WSE、Torus HPC | InfiniBand Fat-Tree、Jupiter |

**关键洞察**：当 N 大到让"每个终端都有 d 个端口"变得不可承受时，必须切换到间接网络。

### 2. Clos 网络 C(n, m, r) — 经典三级结构

```
        输入级          中间级          输出级
       (r 个          (m 个           (r 个
        n×m 交叉点)    m×m 交叉点)     m×n 交叉点)
       ┌─────┐       ┌─────┐         ┌─────┐
       │IM₁  │       │M₁   │         │MO₁  │
源 ──→ │IM₂  │──→   │M₂   │  ──→    │MO₂  │ ──→ 目的
       │...  │       │...  │         │...  │
       │IMᵣ  │       │Mₘ   │         │MOᵣ  │
       └─────┘       └─────┘         └─────┘
```

**参数定义**：
- `n`：每个输入模块的源端数（输入模块数 = r）
- `m`：中间模块数
- `r`：每个输入/输出模块的端口数

**无阻塞定理（Clos 定理）**：
- **严格无阻塞 (Strictly Non-Blocking, SNB)**：m ≥ 2r − 1
- **可重排无阻塞 (Rearrangeably Non-Blocking, RNB)**：m ≥ r

**记忆技巧**：m ≥ 2r − 1 是保证"任意时刻建立新连接都不会冲突"的最少中间模块数。

### 3. Fat-Tree — Leiserson 的"代价等价"思想

**核心洞察**：让每一层链路的**带宽**等于该层节点的所有子树带宽之和，这样网络任意切割都是"无瓶颈"的。

```
            核心层 (Core)         ← 1 个 Layer-3 交换节点
           /     |     \
         L2 交换机 × k²/4          ← 聚合层
        /  \   /  \   /  \
      L1 交换机 × k²/2             ← 接入层
     /|/|...  (k³/4 个端节点)
```

**关键定理（Fat-Tree Cost）**：构造一个 k-port 的 Fat-Tree 容纳 N = k³/4 个端节点，总链路数 ≈ N·log N 的系数级，而**每个端节点的成本为 O(1)**。

**与 WSE 的对比**：WSE 的 90 万 PE 仍然在直连网络（Mesh）的代价可承受范围内，但若要做 90 万节点的集群互连，Fat-Tree 是唯一可扩展方案。

### 4. Beneš 网络 — 可重排无阻塞

- 结构：log₂(N) 级 2×2 交换节点，每级之间有完美洗牌连接
- 特性：**RNB**（如果已有连接可以重排，可建立任意新连接）
- 应用：电信交换、并行计算中的洗牌网络

### 5. 实际应用速查

| 系统 | 拓扑 | 规模 | 特点 |
|------|------|------|------|
| **InfiniBand HDR** | Fat-Tree (2 层) | 数千节点 | 子网管理 + 自适应路由 |
| **Google Jupiter** | 6 阶段 Clos | 数十万端口 | 集中式流量工程 |
| **Microsoft Azure** | Fat-Tree (Sonic) | 数十万端口 | 端到端无损 |
| **Tofino 交换机** | 多级 Clos | 64-256 端口 | P4 可编程 |
| **Intel Omni-Path** | Fat-Tree | 数千节点 | 链路级流量控制 |

## 🧪 练习题（约 45-60 分钟）

### 基础题
**Q1**：证明 C(3, 5, 3) 是否严格无阻塞？需要多少个交叉点？

> 答：m=5, r=3 → m ≥ 2r − 1 = 5 → 满足，**严格无阻塞** ✓
> 输入级：3 个 3×5 交叉点 = 15
> 中间级：5 个 5×5 交叉点 = 25
> 输出级：3 个 5×3 交叉点 = 15
> **总交叉点：55**
> 总端节点：3×3 = 9

**Q2**：画出一个 **4-ary Fat-Tree** 的拓扑结构（提示：k=4 表示每个交换节点有 4 个端口）。

> 答：4-ary Fat-Tree 共 16 个端节点：
> - 8 个 L1 接入交换机（每个接 2 个端点）
> - 4 个 L2 汇聚交换机
> - 链路：端→L1 是 1Gbps，L1→L2 是 2Gbps，L2→核心是 4Gbps
> - 每条"向上"链路带宽翻倍，确保无瓶颈

**Q3**：设计一个连接 **64 个端节点**的 Clos 网络（每个端节点 1 个端口）。要求：每个输入模块能处理 r 个端节点，中间模块数尽量少。计算需要多少交换节点？

> 答：选 r=8（输入模块规模），则需要 64/8 = 8 个输入模块。
> 严格无阻塞条件：m ≥ 2r − 1 = 15。
> 取 m=15，则每个输入模块 8×15=120 个交叉点，中间模块 15×15=225，输出模块 15×8=120。
> **总交叉点：8×120 + 15×225 + 8×120 = 960 + 3375 + 960 = 5295 个交叉点**
> **总交换模块：8 + 15 + 8 = 31 个**

### 进阶题（与研究关联）
**Q4**：InfiniBand HDR (200Gb/s) 的 Fat-Tree 子网最多支持 4096 个端节点。如果扩展到 10 万端节点，需要做什么设计调整？

> 思考点：
> - 二级 Fat-Tree 不够 → 需要三级（Clos）
> - 子网管理开销：单个 Subnet Manager 处理不了 → 需要分层 SM
> - 路由表规模爆炸：L2/L3 需要 ECMP + 自适应路由
> - **关键**：Fat-Tree 的"对称性"在高基数下会破坏 → 现代做法是"伪随机"Clos

**Q5**：Cerebras WSE-3 有 ~90 万 PE，用 2D Mesh。如果 WSE 想通过 off-chip 互连把 16 颗 WSE 连成一个"Wafer-Scale Cluster"，哪种间接网络最合适？为什么？

> 答：推荐 **Dragonfly** 或 **Dragonfly+**（不是直接 Fat-Tree）：
> - 16 颗 WSE 远小于"数据中心级"规模 → Fat-Tree 的成本浪费
> - 但又远超单机柜 → Torus 直径太长
> - Dragonfly 通过"分组 + 全连接"在两者间找到甜点
> - 这也是今天学习的间接网络思想向"层次化拓扑"的延伸（见 Day 9 高基数路由）
