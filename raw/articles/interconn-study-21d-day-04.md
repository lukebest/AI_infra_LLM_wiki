## 今日主题：拓扑基础 II — 把"指标"翻译成"成本和性能"

### 🧭 为什么今天学这个？

昨天你学会了 5 个**度量指标**（度、直径、平均距离、二分带宽、节点对称性）。但这些指标**不是免费的**——每个指标背后都对应着真金白银的**硬件成本**：

- **直径 ↓** → 链路 ↑ 或 度 ↑
- **二分带宽 ↑** → 链路 ↑（Torus 比 Mesh 多 33% 链路）
- **度 ↓** → 直径 ↑、吞吐量 ↓

今天你要学**如何把这套权衡写成公式**，并用它判断一个拓扑**实际能不能造、值不值得造**。这是基础篇的收官——明天起进入**拓扑设计全面解析**（Clos/Fat-Tree/Butterfly），今天的成本模型就是那把钥匙。

## 🔑 核心概念（必须掌握）

### 1. 三类成本

| 成本 | 含义 | 度量 | 物理对应 |
|------|------|------|----------|
| **节点成本 (Node Cost)** | 每个节点的端口数 | 度 d | 芯片引脚、SerDes 数量 |
| **链路成本 (Link Cost)** | 总链路数和布线 | 链路数 L、总线长 | PCB 走线、硅片 wire |
| **交换成本 (Switch Cost)** | 路由器/交换机的复杂度 | 端口数、缓冲区 | 芯片面积、功耗 |

**关键洞察**：**节点成本最硬**——芯片引脚数受限于封装，不可能无限增长。**链路成本是软成本**——可以用更多 PCB 层、更多光模块解决，但功耗和延迟会飙升。

### 2. 延迟模型（必背！）

**零负载延迟公式**：

```
T = T_hops × (T_router + T_wire) + T_serial
  = H × (T_r + T_w) + L_packet / B_link
```

| 参数 | 含义 | 典型值 |
|------|------|--------|
| H | 跳数（hops） | 由拓扑和路由决定 |
| T_r | 单个路由器延迟 | 1-10 ns（取决于流水线深度） |
| T_w | 单段 wire delay | 片上 1-5 ns（与距离成正比） |
| L_packet | 包长（字节） | 64 B - 1500 B |
| B_link | 链路带宽（字节/秒） | 片上 ~10 GB/s，机柜 ~25 GB/s |

**低负载下**：延迟由**跳数 × 单跳延迟**主导。
**高负载下**：延迟还要加上**排队延迟**（拥塞）— 这是后两周的话题。

### 3. 吞吐量模型

**最大注入带宽约束**（每个节点）：
```
B_inject ≤ d × B_link
```

**最大接受带宽约束**（聚合到所有目的）：
```
B_accept ≤ d × B_link × N / H_avg    （保守估计）
```

**二分带宽是吞吐量上界**：
```
B_total ≤ B_bisection = (B_b) × B_link
```

**关键洞察**：**二分带宽是聚合吞吐量的硬上界**——任何流量模式的聚合吞吐量都不可能超过它。这也是为什么所有 HPC 系统的设计都把二分带宽作为第一指标。

### 4. 直连网络的最优度：对数公式（重点！）

**定理**：对于直连网络，**最优节点度 d ≈ O(log N)**，其中 N 是节点数。

**直觉推导**：
- 网络半径（直径的一半）= H_avg ≈ N^(1/d) / 2（高维超立方体的距离）
- 总链路数 L ≈ N × d / 2（每条链路被两个节点共享）
- 二分带宽 ≈ N × d / 2（垂直切几乎要切到一半链路）

**最优条件**：当 H_avg × B_bisection 达到最优时，d ≈ log N。

**经典数据点**：
| N (节点数) | 最优度 d | 最优拓扑 |
|------------|---------|---------|
| 16 | 4 | 2-D Mesh/Torus |
| 64 | 6 | 3-D Torus |
| 1024 | 10 | Hypercube 或 Fat-Tree |
| 1M | ~20 | 高基数 Switch + Fat-Tree |

**关键洞察**：**直连网络无法扩展到百万级**——因为最优度 d ≈ log N = 20，每个节点需要 20 个端口，造不出来。百万级系统必须用**间接网络 + 高基数 Switch**（这是 Day 7-9 的主题）。

### 5. 低维 vs 高维拓扑（核心权衡）

```
低维（d=2, 3, 4）：Mesh、Torus
  ✅ 节点端口少（2-4）
  ✅ 物理布线简单（局部短连线）
  ❌ 直径大 → 平均跳数多
  ❌ 二分带宽受限

高维（d=log N）：Hypercube、Butterfly
  ✅ 直径小（log N）
  ✅ 二分带宽大
  ❌ 节点端口多（log N）
  ❌ 长连线多（维度间跳跃）
```

**经典经验法则**（Dally 1990 论文）：
- **NoC**：低维 Mesh/Torus（端口数受限于芯片引脚）
- **HPC 机柜**：中等维度 3-D Torus（端口数 6-8 可行）
- **超算**：高维 Torus + 高基数 Switch（端口数 10+）

### 6. 设计原则总结（Dally 视角）

1. **带宽优先**：在所有指标中，**二分带宽**最重要
2. **约束端口**：直连网络 ≤ 4-8 端口（受限于芯片引脚）
3. **局部最优**：Mesh 之所以主导 NoC，是因为它的链路都是局部短连线
4. **避免长 wire**：长 wire = 高延迟 + 高功耗，能避免就避免
5. **二分带宽 = 吞吐量上界**：所有流量优化的目标都是打满 B_bisection

## 🧪 练习题（约 60-90 分钟）

### 基础题

**Q1**：给定 N=64 节点，比较 Mesh(8×8) 和 Torus(8×8) 的成本和性能。

| 指标 | Mesh(8×8) | Torus(8×8) | 差异 |
|------|-----------|-----------|------|
| 节点数 N | 64 | 64 | — |
| 总链路数 L | 2×8×7 = 112 | 2×8×8 = 128 | +14% |
| 平均度 d | ~3.75 | 4 | +7% |
| 直径 D | 14 | 8 | -43% |
| 二分带宽 B_b（链路） | 8 | 16 | +100% |
| 链路成本（"链路口"） | 224 | 256 | +14% |

**关键洞察**：Torus 用**多 14% 的链路**换来**直径↓43%、二分带宽↑100%**。在能造出来的场景下，Torus 通常优于 Mesh。

**Q2**：零负载延迟计算。8×8 Mesh，每跳 2 ns router delay + 1 ns wire delay，64 B packet，链路带宽 16 GB/s。最坏延迟是多少？

```
最坏跳数（对角）：H = 7 + 7 = 14 跳
T_hops = 14 × (2 + 1) = 42 ns
T_serial = 64 B / 16 GB/s = 64 / 16×10^9 = 4 ns
T_total = 42 + 4 = 46 ns
```

**关键洞察**：46 ns 在 LLM 推理中是什么概念？—— 一次 attention 的 QK^T 计算如果涉及跨芯片通信，就要花这个延迟。这是**为什么片上互连追求亚纳秒级**，而片间互连难以满足 LLM 的延迟需求。

**Q3**：最大注入带宽 vs 最大接受带宽分析。8×8 Mesh，节点端口 4，链路带宽 1 GB/s。
- 每个节点最大注入带宽 = d × B_link = 4 × 1 = 4 GB/s
- 64 节点最大聚合注入 = 64 × 4 = 256 GB/s
- 二分带宽 = 8 × 1 = 8 GB/s
- **结论：聚合注入带宽 256 GB/s ≫ 二分带宽 8 GB/s，差 32 倍**
- **这意味着不可能所有节点同时满速注入——必须靠流量局部性**

### 进阶题（与研究关联）

**Q4**：WSE-3 有 ~900,000 PE，2-D Mesh，每跳 2 ns router + 1 ns wire。
- 最坏延迟（PE→对角 PE）= ?
- 如果 PE 间通信 100 次/推理 token，总通信延迟 = ?

```
直径 ≈ 1896 跳
最坏延迟 = 1896 × (2 + 1) + 4 ≈ 5692 ns ≈ 5.7 μs
100 次通信 = 569.2 μs ≈ 0.57 ms
```

**对比**：A100 GPU 上的 HBM 访问延迟 ~300 ns。WSE 的**最坏跨 PE 通信延迟是 HBM 访问的 ~19 倍**——这是 WSE 的**根本物理瓶颈**。

**Q5**：WSE 为什么必须优化"通信局部性"？（结合 Q3 的 32 倍差距）

> 答：
> - WSE 的二分带宽 = 949 条链路 × 4 GB/s ≈ 3.8 TB/s
> - 满注入聚合带宽 ≈ 900,000 × 4 GB/s = 3.6 PB/s
> - **差距 947 倍**！
> - 这意味着**不可能所有 PE 同时注入满带宽**
> - LLM 推理必须在 WSE 上做**算子融合**（相邻 PE 通信）+ **kernel 内通信**（避免跨 PE 流量）
> - 这就是为什么 Cerebras 强调**通信和计算的重叠**——硬件必须支持**细粒度同步**和**低延迟核内通信**

**Q6**：为什么 Cerebras 选择 2-D Mesh 而不是 3-D Torus 或 Hypercube？用今天的成本模型解释。

> 答：
> - 2-D Mesh：每个 PE 只需 4 个端口（✅ 芯片可造）
> - 3-D Torus：需要 6 个端口 + 跨整个硅片的环绕长连线（❌ 长 wire 成本高）
> - Hypercube：949 个 PE 需要 log₂(900000) ≈ 20 个端口（❌ 完全不可行）
> - 关键约束：**芯片引脚数**（PE 端口数 ≪ log N）
> - 即使 2-D Mesh 的二分带宽不理想，**它是"能造出来的最优"**——这就是 Dally 原则的实战

## 🧪 阶段自测（基础篇总结）

### 必须能默写：

**Q7**：互连网络设计空间的 4 层是什么？每层的核心问题是什么？

> 答：
> 1. **拓扑 (Topology)**：节点和链路怎么连？→ 决定物理可达性、成本、性能上界
> 2. **路由 (Routing)**：包走哪条路径？→ 决定实际路径、性能、是否死锁
> 3. **流控 (Flow Control)**：资源怎么分配？→ 决定缓冲/带宽利用率、是否拥塞
> 4. **微架构 (Microarchitecture)**：路由器怎么实现？→ 决定硬件复杂度、单跳延迟、面积功耗

**Q8**：直连网络 vs 间接网络的本质区别是什么？

> 答：
> - **直连**：节点 = 计算 + 路由，每个节点端口数受限于芯片引脚 → 受 O(log N) 约束
> - **间接**：终端节点不路由，路由在专门的 Switch 上 → Switch 端口数可以更高 → 可扩展到百万级

**Q9**：为什么二分带宽是吞吐量上界？给一个反例说明它**不是**永远能被打满。

> 答：
> - 上界：任何流量模式的聚合吞吐量都不可能超过二分带宽（流量必须穿过切割）
> - 反例：**热点流量**（all-to-one，如 AllReduce 末段）——大量流量汇聚到少数节点，即使二分带宽很大，**目的节点的接收带宽**会成为瓶颈
> - **关键洞察**：二分带宽是必要条件，不是充分条件
