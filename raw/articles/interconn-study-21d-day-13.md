## 今日主题：从"会跑"到"不会卡死"——死锁的形式化与破解

### 🧭 为什么今天学这个？

昨天学了 **自适应路由**——报文能感知拥塞、动态绕路。听起来很美，但工程师会立刻警觉一个问题：

> **"报文在路由器间转圈圈，死锁了怎么办？"**

这就是 **死锁（Deadlock）**：报文互相**循环等待**对方的资源，谁也走不了。本质上是操作系统里哲学家就餐问题的网络版。

今天要解决三个根本问题：

1. **如何形式化定义死锁？**（CDG 通道依赖图）
2. **什么条件下路由能保证不死锁？**（Dally & Seitz 定理，1987）
3. **Torus 为什么天生危险？**（环绕链路带来的依赖环 + dateline 方案）

这一章是整个互连网络路由理论**最硬核也最工程化**的一块。理解它，你才能看懂为什么 Torus 至少需要 2 条 VC、为什么 WSE 不用 Torus 而用 Mesh。

## 🔑 核心概念（必须掌握）

### 1. 死锁的直觉：四个报文卡在 2×2 Mesh 上

```
2×2 Mesh，DOR 路由（先 X 后 Y）

    ┌─────────────────────────┐
    │  (0,1)─────────→(1,1)   │
    │    ↑              │     │
    │    │              ↓     │
    │  (0,0)─────────→(1,0)   │
    └─────────────────────────┘

场景：
  A: (0,0) → (1,1) 走 X+ → Y+
  B: (1,0) → (0,1) 走 X- → Y+
  C: 想要 X- 但被 B 占用 → 等
  D: 想要 Y+ 但被 A 占用 → 等
  ... 循环等待 → 死锁！
```

**关键观察**：
- 每个报文**持有**一条链路，**等待**另一条链路
- 报文**不会主动释放**已占用的资源（虫孔交换下尤其严重）
- 网络**完全阻塞**，但每个报文都在"正常"等待 → 难以检测

### 2. 为什么虫孔交换更容易死锁？

对比三种流控的死锁易感性：

| 流控方式 | 缓冲占用 | 死锁临界状态 |
|----------|----------|--------------|
| **Store-and-Forward** | 整个 packet | 报文不会跨链路等待（到节点才换链路）|
| **Virtual Cut-Through** | 整个 packet | 同上 |
| **Wormhole（虫孔）** | **单个 flit** | 报文**横跨多条链路**，每条链路上只有 1 flit → 持有多条资源等待 |

**Wormhole 的致命特性**：一个报文可能**同时占用 4 条链路**（4-flit 报文横穿 4 跳），每条链路上只有 1 个 flit buffer。这种"分布式占用"让死锁概率**指数级上升**。

**工程影响**：Wormhole 几乎**必须**配无死锁路由算法。Store-and-Forward 可以靠大缓冲容忍，但吞吐差。

### 3. 通道依赖图 (Channel Dependence Graph, CDG) — 死锁的显微镜

**CDG 定义**（形式化）：
```
节点 (Vertex)：网络中的每个**通道**（channel = 物理链路或 VC）
边 (Edge)：通道 c₁ → 通道 c₂，表示"占用 c₁ 的报文可能接着请求 c₂"

CDG 有环  ⇔  网络可能死锁
CDG 无环  ⇔  网络无死锁
```

**为什么"CDG 无环 = 无死锁"？**

反证法：
- 假设网络死锁 → 存在一组报文 P₁, P₂, ..., Pₖ 循环等待
- 每个 Pᵢ 持有通道 cᵢ、等待通道 cᵢ₊₁（cₖ 等待 c₁）
- 那么 CDG 中存在 c₁ → c₂ → ... → cₖ → c₁ 的环
- 矛盾！所以死锁 ⇔ CDG 有环

**通道 vs 链路 vs VC 的区分**：
- **物理链路 (Physical Link)**：两点间的物理连接
- **通道 (Channel)**：可以是一条物理链路，也可以是物理链路上的一条 VC
- **CDG 的节点是通道**，不是节点路由器

### 4. 在 2×2 Mesh 上画 XY 路由的 CDG

```
物理链路：
  V₀ = (0,0)→(1,0)   (X+, 第0行)
  V₁ = (0,1)→(1,1)   (X+, 第1行)
  H₀ = (1,0)→(1,1)   (Y+, 第1列)
  H₁ = (0,0)→(0,1)   (Y+, 第0列)
  还有4条返回方向...但XY路由只用朝D方向

XY 路由下报文占用的链路序列：
  (0,0) → (1,0) → (1,1)  ：用 V₀ → H₀
  (0,1) → (1,1)          ：用 V₁
  (0,0) → (0,1) → (1,1)  ：用 H₁ → H₀

CDG 边：
  V₀ → H₀  (走X+后必须走Y+)
  V₁ → H₀  (走X+后必须走Y+)
  H₁ → H₀  (走Y+第0列后必须走Y+第1列)

         V₀  V₁
          \  /
           ↓
          H₀

CDG 树状，无环 → XY 路由在 2×2 Mesh 上**无死锁**
```

**关键洞察**：Mesh 上 XY 路由**永远无环**——因为维序约束保证依赖边只能从 X 维指向 Y 维，**不可能形成回边**。

### 5. 在 3×3 Torus 上画 DOR 的 CDG（为什么死锁？）

```
3×3 Torus，X 维环绕：(2,*) → (0,*)（wrap-around）

XY 路由下，环绕链路 e_X = (2,*)→(0,*) 也被使用

CDG 节点：每条 X+ 链路 + 每条 Y+ 链路
CDG 边：X+ → Y+（同 Mesh）

但在 Torus 上，X+ 链路**形成环**！
  (0,0)→(1,0)→(2,0)→(0,0)  ← X+ 链路环

CDG 边：
  X+(0,0) → Y+(0,0)        (走完X+就走Y+)
  X+(1,0) → Y+(1,0)
  X+(2,0) → Y+(2,0)
  X+(0,1) → Y+(0,1)
  ... etc

但 Torus 上的 X+ 链路连成环，所以：
  X+(0,0) → X+(1,0) → X+(2,0) → X+(0,0)  ← 链路环！

CDG 中存在 X+ 链路构成的子环 → **死锁可能**
```

**为什么 Mesh 安全而 Torus 危险？**
- Mesh 的 X 维是**有界的**（起点 → 终点单向，没有环绕）
- Torus 的 X 维**首尾相连**，X+ 通道构成循环依赖
- **死锁场景**：(0,0)→(1,0)→(2,0) 想再走到 (0,0)？不可能（已到目标）。但 (2,0) → (0,0) 的环绕链路**独立于** (0,0)→(1,0)，**两个报文可以分别占用形成循环等待**

```
3×3 Torus 上 4 个报文卡死：

P₁: (0,0) → (1,0) → (2,0) → (0,0)  [绕过绕链路]
P₂: (1,0) → (2,0) → (0,0) → (1,0)
P₃: (2,0) → (0,0) → (1,0) → (2,0)
P₄: (0,0) → (1,0) → (2,0) → (0,0)

所有报文想用环绕链路 e = (2,0)→(0,0)
所有报文等不到 → 死锁
```

### 6. 解决方案 1：Dateline Scheme（最小代价修复）

**核心思想**：把环绕链路"打断"——规定 **某些报文必须避开环绕链路**（绕远走）。

**Dateline 定义**：
```
选定一条虚拟分割线（如 (2,0)→(0,0) 这条环绕链路）
- 报文到达 (2,0) 时，如果目标在 (0,0) 方向，**先在 X- 方向多走 1 步到 (1,0)** 再继续 XY
- 等价于：把所有 (2,0)→(0,0) 的虚拟跨越都搬到 (1,0)→(0,0) 上
```

**新的 CDG**：
```
X+ 链路环被"切断"：
  X+(2,0) → X+(0,0) 这条 CDG 边**消失**（dateline 强制绕路）
  
剩下的 X+ 链路变成树状 → 无环 → 无死锁
```

**代价**：每个 (2,*) 节点的报文必须多走 1 跳才能到 (0,*)。**延迟增加 1 跳 / k**（k 是维度大小），但**避免死锁**。

**工业实践**：早期 Cray T3D/T3E 用 dateline scheme 跑 DOR。

### 7. 解决方案 2：虚通道（VC）打破依赖环

**核心思想**：**把一条物理链路切成多条 VC，每条 VC 在 CDG 中是独立节点**。

```
3×3 Torus，单条 X+ 物理链路 → 切为 2 条 VC：VC₀ 和 VC₁

报文使用规则（class-based routing）：
- 偶数报文只用 VC₀
- 奇数报文只用 VC₁
- 或：按某种规则决定 VC 选择，保证 VC 间的依赖也形成 DAG

CDG 重新设计：
  X+(2,0) VC₀ → X+(0,0) VC₁  （跨越切换 VC）
  X+(0,0) VC₁ → X+(1,0) VC₀  （跨越切换 VC）
  ...

VC₀ 和 VC₁ 的依赖**交替进行** → 整体依赖图仍然有环！

关键：必须设计 VC 分配规则，让**所有 VC 的依赖图合并后仍然无环**
```

**经典结果**：Torus 上 DOR 需要 **至少 2 条 VC** 才能无死锁（Dally 1987）。1 条 VC 必死锁。

**Mesh 上**：**1 条 VC 就够**（因为维度有限，不会形成 X 维环）。

### 8. Dally & Seitz 无死锁定理（1987）— 互连网络路由的奠基定理

**定理陈述**（**必须能默写**）：

> 给定一个互连网络 $I$ 和一个路由函数 $R$。
> 构造通道依赖图 $D$：
> - $D$ 的节点 = 网络 $I$ 中的所有通道
> - $D$ 中存在边 $c_1 \to c_2$ 当且仅当存在合法报文，使得报文先占用 $c_1$，紧接着请求 $c_2$
>
> **$R$ 无死锁** $\iff$ **$D$ 中无环**

**证明思路**（**要能复述**）：
- (⇒) 反证：若 $D$ 有环 $c_1 \to c_2 \to \ldots \to c_k \to c_1$，则构造 $k$ 个报文分别占用 $c_i$ 等 $c_{i+1}$，形成循环等待 → 死锁
- (⇐) 反证：若网络死锁，则存在循环等待的报文组，每对相邻占用构成 $D$ 中一条边 → $D$ 有环

**推论 1**：要给路由算法证明无死锁，只需画 CDG 看是否无环

**推论 2**：CDG 中所有 cycle 必须被打断（用 dateline、VC 维序等）

**推论 3**：Torus 的 DOR 至少要 2 条 VC（1 条 VC 必有环）

### 9. 死锁避免 vs 死锁恢复

| 策略 | 思想 | 优点 | 缺点 |
|------|------|------|------|
| **死锁避免 (Avoidance)** | 设计路由使 CDG 无环 | 简单、有保证 | 路径受限（如 DOR 不能完全自适应）|
| **死锁恢复 (Recovery)** | 允许死锁，检测后杀死部分报文 | 路径自由、吞吐高 | 需要检测电路、报文可能丢失（需重传）|

**工业选择**：
- **HPC（InfiniBand、NVLink）**：避免（保证延迟确定性）
- **数据中心（部分 TCP/IP 路径）**：恢复（容忍重传）
- **WSE/NoC**：避免（短报文、不可重传）

### 10. 工程启示：为什么 WSE 不用 Torus？

WSE-2/3 是 **~949×949 2D Mesh**，**不是 Torus**。

**关键原因**：
1. **Torus 的环绕链路是片上长线**——在 wafer 上跨越最远的距离，**延迟大、功耗高**
2. **Torus 需要至少 2 条 VC**——每个 PE 路由器缓冲翻倍，**面积代价大**
3. **WSE 流量局部性极强**——LLM 推理中相邻 PE 通信占 ~80%，**极少用到环绕链路**
4. **Mesh 的 CDG 简单**——单 VC、无 dateline，**硬件简单、验证容易**

**对比**：
- **Cerebras WSE**：2D Mesh，无环绕，单 VC，XY 路由
- **NVIDIA GPU**：NVSwitch + Clos（不是 Torus）
- **TPU v4**：3D Torus（Google 选择，但用特殊 OCS 光学重构）
- **Intel Xeon Phi (Knights Landing)**：Mesh 2D

**Torus 的复兴**：Google TPU v4 用 3D Torus + 光学电路交换（OCS），**重新让 Torus 有用**——但代价是 OCS 增加硬件复杂度。

### 基础题

**Q1**：在 **3×3 Mesh**（**不是** Torus）上，画出 **XY 路由**的完整 CDG（所有 X+ 和 Y+ 通道）。说明为什么这个 CDG 无环。

> 答：
> 
> 物理链路（双向 Mesh 上 XY 路由只考虑朝 D 方向的链路）：
> - X+ 链路：3 行 × 2 条 = 6 条（每行 (0,1), (1,2) 两段）
> - Y+ 链路：3 列 × 2 条 = 6 条
> - 共 12 条通道
> 
> CDG 边（XY 路由下，一条报文在每条 X+ 链路后必然走 Y+ 链路）：
> - 6 条 X+ → 6 条 Y+（每条 X+ 后面都有出度为 1 的 Y+）
> 
> CDG 结构：
> ```
>   [6 个 X+ 节点]  →  [6 个 Y+ 节点]
> ```
> 
> 无环判定：从 X+ 节点出发只能到达 Y+ 节点，从 Y+ 节点**没有出边**（走完 Y+ 就到达目标）。所以图是 **DAG（树状）**，**无环** → XY 路由在 3×3 Mesh 上**无死锁** ✅

**Q2**：在 **3×3 Torus** 上画出 **XY 路由**的 CDG，指出 **哪条 X+ 链路形成环**。然后 **用 dateline scheme** 修复，画出修复后的 CDG。

> 答：
> 
> 3×3 Torus 上，X+ 物理链路：
> - 普通 X+：每行 (0,1), (1,2)，共 6 条
> - **环绕 X+**：每行 (2,0)，共 3 条
> - 合计 9 条 X+ 链路
> 
> 环状结构（只看 X+ 链路之间）：
> ```
>   (0,0)→(1,0) → (1,0)→(2,0) → (2,0)→(0,0)  ← 环绕
>      ↑________________________________________|
> ```
> 
> 这构成 X+ 通道的环 → **CDG 有环** → XY 路由在 3×3 Torus 上**会死锁** ❌
> 
> **Dateline 修复**：
> - 选环绕链路 e = (2,0)→(0,0) 为 dateline
> - 规则：报文从 (2,*) 要去 (0,*) 时，**先走 X- 多 1 步**到 (1,*) 再继续 XY
> - 等价于：把跨越 dateline 的流量**强制搬到 (1,0)→(1,0) 等内部链路上**
> 
> 修复后 CDG：环绕链路 e 不再被任何报文"穿过"（dateline 强制绕路）→ X+ 链路不再形成环 → 无环 ✅

**Q3**：证明 **3×3 Torus 上 DOR 需要至少 2 条 VC** 才能无死锁。（提示：反证 + VC 数量与 CDG 复杂度的关系）

> 答：
> 
> 反证法（假设 1 VC 足够）：
> - 1 VC = 1 条逻辑通道 / 物理链路
> - CDG 中 X+ 链路形成环（见 Q2）
> - 任何路由函数（确定性或自适应）都**无法打破这个环**，因为 X+ 链路本身就物理上首尾相连
> - 任何从 (0,0) 到 (2,0) 的报文必然**沿 X+ 方向经过至少 1 条 X+ 链路**，与从 (2,0) 回 (0,0) 的报文形成对偶
> - 必然存在报文对 (P, Q) 使得 P 占 X+(0,0)→(1,0)，Q 占 X+(2,0)→(0,0)，P 等 Q 的 X+(1,0)→(2,0)... 等等，复杂循环
> - 严格证明用 Dally 定理：1 VC 时 CDG 节点 = 物理通道数，X+ 通道本身构成子环 → CDG 有环 → 死锁
> 
> 用 2 条 VC：
> - 把每条物理链路切成 VC₀ 和 VC₁
> - 路由规则：报文使用 VC 取决于**经过 dateline 的次数**
>   - 未跨 dateline → VC₀
>   - 已跨 1 次 → VC₁
> - **VC₁ 的报文不能再跨 dateline**（即不能再用环绕链路）
> - 新的 CDG：X+ VC₀ 和 X+ VC₁ 的依赖图**合并**后，**没有从 VC₁ 回 VC₀ 的边**
> - 拓扑序：VC₀ → VC₁ → Y+ VC → (目标)
> - **DAG，无环** ✅

### 进阶题（与研究关联）

**Q4**：Cerebras WSE-2 是 **~757×757 Mesh**（WSE-3 ~949×949）。如果**改用 Torus**（加环绕链路），估算需要：
- (a) 每个 PE 路由器的 VC 数量变化
- (b) 每条链路的缓冲大小变化
- (c) 为什么 Cerebras 选择了 Mesh 而不是 Torus？

> 答：
> 
> - (a) **VC 数量**：Mesh 上单 VC 足够；Torus 上 DOR 需要 ≥ 2 条 VC（dateline scheme）或 ≥ 4 条 VC（Duato 完全自适应）
> - (b) **缓冲大小**：假设总缓冲预算固定（如 16 flits/端口）：
>   - Mesh 单 VC：1 × 16 flits = **16 flits/VC**
>   - Torus 2 VC：2 × 8 flits = **8 flits/VC**（VC 变浅）
>   - Torus 4 VC：4 × 4 flits = **4 flits/VC**（VC 很浅，HOL blocking 风险）
> - (c) **Cerebras 选 Mesh 的理由**：
>   1. **面积**：Torus 环绕链路是 wafer 上**最长连线**，功耗和延迟代价大
>   2. **缓冲**：Mesh 单 VC，缓冲集中（深度大），Torus 多 VC，缓冲浅（深度小），**单流性能差**
>   3. **流量**：LLM 推理中 ~80% 流量是相邻 PE（1-3 跳），**极少需要环绕**
>   4. **验证**：Mesh CDG 是简单 DAG，硬件验证容易；Torus CDG 是多 VC DAG，**验证复杂度指数级**
>   5. **良率**：环绕链路是 wafer 上**最长的连线**，**最易出现制造缺陷**，单点失效导致整片 wafer 报废

**Q5**：**LLM 训练中的梯度同步**（AllReduce）流量。假设 64 个 GPU 组成 **4×4×4 3D Torus**（如 Google TPU v4 风格）。
- (a) 为什么 3D Torus 比 2D Torus 更适合 AllReduce？
- (b) 如果改用 Mesh，AllReduce 性能会下降多少（粗估）？
- (c) 维度选择（2D vs 3D vs 4D）对 Torus 死锁避免有什么影响？

> 答：
> 
> - (a) **3D Torus 适合 AllReduce 的原因**：
>   - AllReduce 是**分层归约**（intra-node → inter-node → root）
>   - 3D Torus 提供 3 个正交维度 → **每个维度独立做 ring-allreduce**
>   - 延迟：3D Torus 直径 = k^(1/3)（vs 2D 的 k^(1/2)）→ 64 节点时
>     - 2D 8×8：直径 = 8
>     - 3D 4×4×4：直径 = 6
>     - 3D 直径更短，AllReduce 步数更少
>   - 带宽：3D Torus 二分带宽 = 4 × k²（每维度都有 wrap-around 提供二分割），比 2D 强
> - (b) **Mesh vs Torus 的 AllReduce 性能**：
>   - Mesh 边缘节点通信必须"绕"，等价于增加了 ~k/2 跳延迟
>   - 8×8 Mesh 边缘对边缘延迟 ≈ 14 跳（vs 8×8 Torus 4 跳）
>   - AllReduce 延迟 = 2 × (N-1) × 单跳延迟 × 步数
>   - **Mesh AllReduce 延迟约为 Torus 的 2-3 倍**
>   - 但 Mesh 路由器简单 + 单 VC，可通过**提高时钟频率**补偿
> - (c) **维度对 Torus 死锁避免的影响**：
>   - 2D Torus：DOR 需要 2 VC（每维度 1 条 VC）
>   - 3D Torus：DOR 需要 **3 VC**（每维度 1 条 VC）—— 因为每个维度都形成环绕环
>   - k-D Torus：DOR 需要 **k VC**（dateline scheme）—— VC 数随维度线性增长
>   - **这就是 4D+ Torus 几乎不用的原因之一**：VC 数太多，缓冲代价太大

**Q6**：**死锁恢复 vs 死锁避免**在 LLM 推理场景下的对比。
- (a) 如果 WSE 路由器**采用死锁恢复**（如检测到死锁就丢弃报文），LLM 推理会怎样？
- (b) 设计一个**轻量级死锁检测器**：每个路由器需要看哪些信号？
- (c) 死锁恢复需要**重传机制**。在片上互连中实现重传有什么挑战？

> 答：
> 
> - (a) **LLM 推理会崩溃**：
>   - LLM 推理的流量**强同步**（如 Attention 计算中的 all-to-all），丢一个报文 → 整批 token 延迟卡住
>   - **LLM 计算不可重传**：权重在内存，重传代价大（读数百 GB）
>   - 即使重传成功，**延迟抖动 > 100μs** → 推理吞吐下降 50%+
>   - **结论**：WSE 必须死锁**避免**，不能恢复
> - (b) **轻量级死锁检测器**：
>   - 每个路由器监控：**所有输入 VC 的报文停留时间**（age counter）
>   - 阈值：如果某报文 age > 1000 cycles 且**所有 VC 的 age 都 > 阈值** → 触发恢复
>   - 更简单：**周期计数器**：每个报文从注入开始计时，> 阈值 → 标记"可能死锁"
>   - **成本**：每个 VC 加 1 个 10-bit 计数器，**面积开销 < 1%**
> - (c) **片上重传的挑战**：
>   1. **缓冲需求**：重传需要保留已发送报文 → 缓冲翻倍
>   2. **协议复杂度**：需要 ACK/NACK + 重传定时器 → 状态机复杂
>   3. **顺序保证**：乱序到达需要重排序 → 大缓冲
>   4. **延迟敏感**：LLM 推理对单报文延迟敏感，重传 1 次可能让整体性能跌 20%
>   5. **良率影响**：片上 SRAM 故障率高，复杂的 ACK/NACK 协议难验证
