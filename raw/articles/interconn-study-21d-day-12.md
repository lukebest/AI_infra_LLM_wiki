## 今日主题：自适应路由 — 让报文自己挑路，绕开拥塞

### 🧭 为什么今天学这个？

昨天学了 **XY 维序路由（DOR）**——它简单、确定、无死锁、是工业标准。但它有个致命缺点：**完全不看网络状态**。某条链路拥塞到死，报文还是要按"先 X 后 Y"硬着头皮冲。

今天学 **自适应路由（Adaptive Routing）**——报文**实时感知**网络拥塞，**动态选择**路径。代价是路由器变复杂 + 死锁避免变难。这是 Mesh 上**自适应 vs 确定性**的经典权衡，也是 WSE/NoC 选型的关键决策点。

## 🔑 核心概念（必须掌握）

### 1. 为什么需要自适应路由？

**XY 路由的痛点**：
```
场景：4×4 Mesh，节点 (0,0) → (3,3)

       (0,3)──(1,3)──(2,3)──(3,3)
         │      │      │      ↑
       (0,2)  (1,2)  (2,2)  (3,2)
         │      │      │      ↑
       (0,1)  (1,1)  (2,1)  (3,1)
         │      │      │      ↑
       (0,0)──(1,0)──(2,0)──(3,0)
                ↓     ↓     ↓

如果所有报文都走 X-first：(0,0)→(3,0) 的链路 (0,0)-(1,0)-(2,0)-(3,0) 满载
→ 拥塞 → 延迟飙升
→ 但自适应路由能"看到"这条链路忙，自动选 Y 先走一部分
```

**关键洞察**：XY 路由把流量**强行固定**到一组链路上。自适应路由让流量**流动**到空闲链路上，**负载均衡**。

### 2. 自适应路由的分类（4 个维度）

| 维度 | 选项 | 含义 |
|------|------|------|
| **最小 vs 非最小** | 最小 | 路径长度 ≤ 最短路径（hops = |Δx|+|Δy|） |
| | 非最小 | 可能绕远（hops > 最短） |
| **完全 vs 部分** | 完全 | **所有**最短路径都可走 |
| | 部分 | 受限（如 turn model） |
| **局部 vs 全局** | 局部 | 路由器只看相邻 VC 拥塞 |
| | 全局 | 看整条路径拥塞（实现复杂） |
| **感知 vs 不感知** | 感知 | 实时读 VC 状态寄存器 |
| | 不感知 | 用概率/轮询（伪自适应） |

**最常见组合**：**最小 + 完全 + 局部 + 感知**（但有死锁问题，明天 Day 13 解决）。

### 3. 最小自适应路由 (Minimal Adaptive)

**定义**：路由器每一步都**贪心选择**一条**最短路径**方向。

```
Mesh 上从 S 到 D，最短路径长度 = |Δx| + |Δy|

每步决策：
  - 如果 Δx ≠ 0：可选 X+ 或 X-（方向朝向 D）
  - 如果 Δy ≠ 0：可选 Y+ 或 Y-
  - 在可选方向中，选**拥塞最低**的那个
```

**例子**：从 (0,0) 到 (3,3)，第一跳选择
```
XY 路由：永远先 X+ → (1,0)
最小自适应：X+ 拥塞 80%，Y+ 拥塞 20% → 选 Y+ → (0,1)
```

**特点**：
- ✅ 路径长度 = 最短（延迟可预测）
- ✅ 拥塞感知 → 负载均衡
- ❌ 完全自适应有死锁（明天讲）
- ❌ 需要每个 VC 报告拥塞状态（硬件成本）

### 4. 非最小自适应路由 (Non-Minimal Adaptive)

**定义**：允许**绕远路**——走非最短路径。

**动机**：当**整条最短路径方向**都拥塞时，唯一解是绕远。

**典型算法**：**Valiant's Randomized Routing (VRR)**
```
1. 在网络中随机选一个中间节点 M
2. 报文先 S → M（最短）
3. 再 M → D（最短）
4. 总路径长度 ≤ 2 × 最短
```

**优点**：
- ✅ 在对抗性流量下仍能负载均衡
- ✅ 形式上无死锁（因为用了**两段最短**路径拼接）

**缺点**：
- ❌ 延迟 = 2× 最短（吞吐换延迟）
- ❌ LLM/AllReduce 这类强同步流量不友好（延迟变成 2 倍）

### 5. 虚通道（VC）为什么是自适应路由的关键？

**核心机制**：**VC 把一条物理链路切成多条逻辑链路**，每条 VC 独立流控。

```
         ┌─────────────────────────────────┐
         │      Physical Channel           │
         │  ┌───┐ ┌───┐ ┌───┐ ┌───┐      │
         │  │VC0│ │VC1│ │VC2│ │VC3│      │
         │  └─┬─┘ └─┬─┘ └─┬─┘ └─┬─┘      │
         └────┼─────┼─────┼─────┼─────────┘
              ↓     ↓     ↓     ↓
           独立缓冲 独立流控 独立分配

为什么能打破死锁？
- 不同 VC 走不同方向 → 打破通道依赖环
- 报文可在 VC 间"切换"以避开阻塞
```

**VC 数量 vs 自适应能力**：
- 1 VC → 只能 DOR（无自适应，死锁风险低）
- 2 VC → 可以做限制自适应（部分 turn 限制）
- 4+ VC → 完全自适应可行

**硬件成本**：每个 VC 需要独立的缓冲（典型 4-8 flits × 4-8 VC = 32-64 flit buffer/端口）。

### 6. 自适应路由的实现：路由器需要看什么？

**每个端口每周期需要的状态**：

| 状态 | 来源 | 用于 |
|------|------|------|
| **VC 占用状态** | 上游 VC 是否有报文 | 避免注入冲突 |
| **VC 缓冲余量** | 下游 credit 计数 | 避免溢出 |
| **VC 队列长度** | 本地缓冲队列 | 拥塞度量 |
| **链路利用率** | 链路忙/闲比 | 拥塞度量 |

**典型拥塞度量**：**VC 缓冲余量**（credit count）——credit 越少 = 下游越忙。

```
路由器伪代码：
function adaptive_route(input_port, vc, dst):
    candidates = []
    for output_port in neighbors:
        if is_progress(input_port, output_port, dst):  # 朝着 D 推进？
            if vc[output_port].credits > threshold:    # 不拥塞？
                candidates.append(output_port)
    return random_choice(candidates)  # 选一个最少拥塞的
```

### 7. 自适应 vs 确定性：什么时候用哪个？

| 场景 | 流量特征 | 推荐路由 | 原因 |
|------|----------|----------|------|
| **HPC AllReduce** | 全局、均匀、强同步 | DOR | 延迟可预测、保序 |
| **NoC 数据流** | 局部、相邻 PE 通信多 | DOR | 简单、低延迟 |
| **数据中心 east-west** | 热点、跨机架 | 自适应（VRR 变体） | 负载均衡关键 |
| **LLM 推理** | 局部（层内）+ 少量全局 | DOR + 偶尔自适应 | 局部流量为主 |
| **内存一致性流量** | 短报文、不规则 | 自适应 | 拥塞敏感 |

**经验法则**：
- 流量**局部性强** → DOR（简单即美）
- 流量**全局且不规则** → 自适应（吞吐换延迟）
- 流量**强同步**（如 AllReduce）→ DOR（确定性保序）

### 8. Duato 理论的预告（明天 Day 13 展开）

**Duato 定理**（1995）解决了"完全自适应路由如何无死锁"的根本问题：

**核心思想**：**双路径** —— 把报文通路分成
- **逃逸子网 (Escape Subnetwork)**：保证无死锁的子集（用 DOR/XY）
- **自适应子网 (Adaptive Subnetwork)**：可任意绕（可能形成环）

**关键定理**：**只要逃逸子网无死锁，整体就无死锁**——因为自适应路径最终都能"逃"到无死锁的子网。

**这意味着**：
- ✅ 完全自适应路由**可以**实现无死锁
- ✅ 路由器有**2 类 VC**：adaptive VC（多）+ escape VC（少）
- ✅ 报文阻塞时切换到 escape VC → 必能到达

明天 Day 13 我们会展开 Duato 理论的形式化证明和 Torus 上需要 2 条 VC 的细节。

## 🧪 练习题（约 45-60 分钟）

### 基础题

**Q1**：在 **4×4 Mesh** 上，从 **(0,0)** 到 **(3,3)**，列出所有**最短路径**（最小自适应可走的路径）。

> 答：
> - 最短跳数 = 6（3 步 X + 3 步 Y）
> - 路径数 = C(6,3) = **20 条**（X+ 出现 3 次的位置选择）
> - 例如：(0,0)→(1,0)→(2,0)→(3,0)→(3,1)→(3,2)→(3,3)（XY 路由）
> -     (0,0)→(1,0)→(1,1)→(2,1)→(3,1)→(3,2)→(3,3)（第 4 步分支）
> -     (0,0)→(0,1)→(1,1)→(2,1)→(2,2)→(3,2)→(3,3)（第 1 步就分支）
> - 完全最小自适应 = 20 条路径都可走（但有死锁风险！）

**Q2**：用 **Valiant's Randomized Routing (VRR)**，从 **(0,0)** 到 **(3,3)**，如果随机选中间节点 **(1,2)**，路径是什么？

> 答：
> - 阶段 1：(0,0) → (1,2) 最短路径（XY 路由）: 1+2 = 3 跳
> -   路径：(0,0) → (1,0) → (1,1) → (1,2)
> - 阶段 2：(1,2) → (3,3) 最短路径（XY 路由）: 2+1 = 3 跳
> -   路径：(1,2) → (2,2) → (3,2) → (3,3)
> - 总跳数 = 3+3 = 6 = **2× 最短**（与直接 XY 一样，但本例是巧合）
> - 在大 Mesh 上 VRR 通常 ≥ 2× 最短（绕远效果）

**Q3**：**自适应路由每端口需要几个 VC** 才能做到完全自适应？为什么？

> 答：
> - 至少 **2 个 VC**（1 个 escape VC + 1 个 adaptive VC）
> - 经典 Duato 方案：**adaptive VC 数 = degree - 1**（Mesh 中 degree=4，则 3 adaptive VC + 1 escape VC = 4 VC）
> - 少 1 个 VC 都会**丢失部分路径**（turn model 限制）
> - Torus 上需要**至少 2 条虚通道**才能用 DOR 无死锁（明天 Day 13 详解）

### 进阶题（与研究关联）

**Q4**：Cerebras WSE-3 有 **~949×949 Mesh**，~90 万 PE。
- (a) 如果每个 PE 路由器有 **4 个 VC**，每个 VC 缓冲 **8 flits**，每个端口的缓冲总量是多少？
- (b) 如果用 DOR（1 VC/端口），每端口缓冲是 8 flits（只有 1 个队列）。改成 4 VC 后总缓冲相同，但可以支持自适应路由。这种"VC 数 vs 缓冲深度"的权衡有什么意义？
- (c) WSE 的**流量特征**（局部性强 + 偶发 AllReduce）下，更适合 DOR 还是自适应路由？为什么？

> 答：
> - (a) 4 VC × 8 flits = **32 flits/端口**
> - (b) **固定缓冲总量**下：
>   - 单 VC 深（32 flits）→ DOR，**延迟抖动小**（一队到底）
>   - 多 VC 浅（4×8 flits）→ 自适应，**可并行处理多流**（避免 HoL blocking）
> - (c) **DOR 更适合 WSE**：
>   - LLM 推理流量**局部性极强**（相邻 PE 通信 ~80%），XY 路径已经接近最优
>   - 自适应路由的**负载均衡收益小**，但**路由器复杂度 + 功耗**增加明显
>   - 大规模 PE 上，路由决策延迟本身（5-10 cycles）会成为瓶颈

**Q5**：你正在设计一个 **256 核 NPU 互连**（16×16 Mesh），每个 NPU 有 **高优先级控制流量**（kernel launch, barrier）和**低优先级数据流量**（tensor move）。
- (a) 如果两类流量都用 XY 路由会发生什么？
- (b) 设计一个**双 VC 路由方案**：VC0 给高优先级，VC1 给低优先级。VC0 总是优先调度。画出路由器分配器的优先级逻辑。
- (c) 这种方案在什么场景下会**失效**？（提示：流量比例极端时）

> 答：
> - (a) **HoL blocking** —— 一个低优先级大报文可能阻塞高优先级小报文
> -   XY 路由下控制报文被迫等数据报文通过 → 延迟不可预测
> - (b) **双 VC 方案**：
>   ```
>   Switch Arbiter:
>     优先级 = [VC0_high, VC1_low]  # strict priority
>     if VC0.has_packet():
>         grant VC0
>     elif VC1.has_packet():
>         grant VC1
>   ```
>   - VC0 永远优先 → 高优先级延迟上界确定
>   - VC1 处理剩余带宽 → 数据流量不影响控制
> - (c) **失效场景**：
>   - VC0 流量 > 70% → VC1 饿死
>   - VC0 流量 < 10% → VC1 单跑（VC0 浪费）
>   - **优化**：weighted round-robin 而非 strict priority，给 VC1 最小保证

**Q6**：**LLM 训练中的 AllReduce 流量**（每个 GPU 同步梯度）。
- (a) AllReduce 是强同步操作，为什么 DOR 比自适应路由更适合？
- (b) 如果 GPU 用 NVLink（不是 Mesh），且 NVLink 是 **Clos/Fat Tree 拓扑**，还需要自适应路由吗？
- (c) 给出**一个自适应路由反而比 DOR 差**的具体场景。

> 答：
> - (a) AllReduce = **树形/环形 collective**，所有 GPU 必须在相似时间内完成。XY 路由**延迟确定** → 所有 GPU 同步代价相同 → 集合效率高
>   自适应路由让不同 GPU 走不同路径 → **延迟发散** → 最慢的拖后腿
> - (b) **不需要自适应** —— Clos/Fat-Tree 的路径多样性本身就是"自带负载均衡"
>   Clos 拓扑上随便走什么路径都能到达（多条等价路径），不需要路由器动态决策
>   NVLink 的设计哲学：**网络结构层面**做负载均衡，路由器**保持简单**
> - (c) **场景**：所有报文都去同一热点（如 LLM 推理中所有 PE 读同一个 embedding 表）
>   - 自适应路由：所有报文都"看到"去热点的路径不拥塞 → 都走同一条 → 全堵
>   - DOR：按 XY 严格分配 → 部分报文走绕远 → **热点流量被分散**
>   - **反直觉**：拥塞均匀时自适应赢，**热点流量时 DOR 反而能避免雪崩**
