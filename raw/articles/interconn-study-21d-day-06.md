## 🔑 核心概念（必须掌握）

### 1. 2-D Mesh：最常见的片上拓扑

```
         列  0   1   2   3
        ┌──┬──┬──┬──┐
  行 0  │(0,0)(0,1)(0,2)(0,3)│  ← 边节点，度=3
        ├──┼──┼──┼──┤
  行 1  │(1,0)(1,1)(1,2)(1,3)│  ← 内部节点，度=4
        ├──┼──┼──┼──┤
  行 2  │(2,0)(2,1)(2,2)(2,3)│  ← 内部节点，度=4
        └──┴──┴──┴──┘
  行 3  ↑ 角节点，度=2
```

| 指标 | 公式（k×k Mesh） | 例：8×8 Mesh |
|------|------------------|--------------|
| **节点数** | N = k² | 64 |
| **链路数** | 2k(k−1) | 112 |
| **内部节点度** | 4 | — |
| **边节点度** | 3 | — |
| **角节点度** | 2 | — |
| **直径** | 2(k−1) | 14 |
| **平均距离** | ≈ 2k/3 | ≈ 5.33 |
| **二分带宽** | k 链路 | 8 链路 |

**关键问题**：Mesh 是**节点非对称**的（边、角、内部节点的度不同），路由时需要特殊处理边缘节点——这是 WSE 论文里经常讨论的"edge case"。

### 2. 2-D Torus：Mesh + Wrap-Around

```
       ←── wrap ──→
      ┌────────────┐
      ▼            │
   ┌──┬──┬──┬──┐   │
   │  │  │  │  │   │  每行首尾相连
   ├──┼──┼──┼──┤   │  每列首尾相连
   │  │  │  │  │   │
   ├──┼──┼──┼──┤   │
   │  │  │  │  │   │
   └──┴──┴──┴──┘   │
                    │
   ←── wrap-around ──┘
```

| 指标 | 公式（k×k Torus） | 例：8×8 Torus |
|------|-------------------|---------------|
| **节点度** | 全部 = 4 | 4 |
| **直径** | 2⌊k/2⌋ | 8 |
| **平均距离** | ≈ k/2 | ≈ 4 |
| **二分带宽** | 2k 链路 | 16 链路 |
| **链路数** | 2k² | 128 |

**Mesh vs Torus 的核心差异**：
- Torus **节点对称**——每个节点度都是 4，路由算法更简单
- Torus **直径减半**（8×8：14 → 8）—— 平均延迟下降 ~40%
- 代价：**多出 16 条 wrap-around 长链路**（物理上是芯片边到边的长线）

### 3. k-ary n-cube：统一表达

Dally 的精髓——**用 k（基数）和 n（维度）表达所有直连网络**：

| 拓扑 | k | n | 节点数 N=k^n |
|------|---|---|--------------|
| 1-D Torus（双向环） | k | 1 | k |
| **2-D Mesh** | k | 2 | k² |
| **2-D Torus** | k | 2 | k² |
| 3-D Torus | k | 3 | k³ |
| **Hypercube** | 2 | n | 2^n |
| 5-D Torus | k | 5 | k^5 |

**关键公式**（Dally 1990 经典结论）：
- **直径** = n × (k−1) / 2（对 Torus）
- **二分带宽** = 4k^{n-1}（对 Torus，每维 2 链路 × k^{n-1} 切点）
- **节点度** = 2n（直连网络）

**Dally 定理（核心结论）**：
> 固定节点度 d = 2n（保持成本），把维度 n 提高、基数 k 降低，可以降低**零负载延迟**——但**吞吐量**先升后降，存在最优维度 d_opt ≈ 2√N。

### 4. 维度-延迟-吞吐量的三角权衡

```
延迟 ↓ ────→ 维度 ↑ ────→ 吞吐量 ↓
   (跳数减少)            (链路利用率下降)
```

直觉：
- **维度↑** → 跳数↓ → 延迟↓ ✓
- **维度↑** → 每条链路被"切"成更多份 → 每份带宽↓ → 瓶颈链路流量↑ → 吞吐量↓ ✗
- 平衡点：在**最优维度 d_opt ≈ 2√N** 时吞吐量最大

这就是为什么：
- **N=64 (8×8)**：2-D Torus 最优（n=2, k=8）
- **N=65536 (Blue Gene/L 64k 节点)**：3-D Torus (n=3, k=40) 或 5-D Torus
- **N=90 万 (WSE-3)**：2-D Mesh 即可（n=2, k≈949）—— 硬件走线限制决定了高维度不现实

### 基础题
**Q1**：画出 3×3×3 的 3-D Torus 结构示意（文字即可），并计算：
- 节点数 N
- 节点度
- 直径
- 二分带宽
- 链路总数

> 答：N=27，度=6，直径=3，二分带宽=18 链路，总链路=81。
> 推导：每个节点 3 维 × 2 方向 = 度 6；直径 = 3 × ⌊3/2⌋ = 3；二分 = 3×3×2 = 18；链路 = 3×27/2 = 81（每条链路被两端共享）。

**Q2**：给定 64 节点，比较以下三种拓扑的直径、平均距离、节点度：
- (a) **8×8 Mesh**
- (b) **4×4×4 Torus**
- (c) **2×2×2×2×2×2 Hypercube**（n=6, k=2）

> 答：
> (a) Mesh: 度 2-4 不等（平均 3.5），直径 14，平均距离 5.33
> (b) Torus: 度=6，直径=6，平均距离≈3
> (c) Hypercube: 度=6，直径=6，平均距离=3.67
> **洞察**：Mesh 节点便宜但延迟最差；Torus 和 Hypercube 直径都是 6，但 Torus 的"成本-延迟"曲线更平滑（更接近最优 d_opt=2√64=16/2=...这里 d_opt=16？核对：2√N=2×8=16，所以 Torus 接近最优）。

**Q3**：在 4×4 Mesh 上，分别用 **XY 维序路由**画出从 (0,0) → (3,3) 和 (0,3) → (3,0) 的路径。为什么维序路由在 Mesh 上无死锁？（不用画 CDG，定性说明即可）

> 答：XY 路由 = 先沿 X 方向走到目标列，再沿 Y 方向走到目标行。
> (0,0)→(3,3)：右走到 (3,0)，再上走到 (3,3) — 共 6 跳。
> (0,3)→(3,0)：右走到 (3,3)，再下走到 (3,0) — 共 6 跳。
> **无死锁的定性原因**：维序路由强制 X 方向的"资源使用"在 Y 方向之前（或反之），所以 Y→X 依赖环被打断，CDG 无环。Day 13 会严格用 CDG 证明。

### 进阶题（与研究关联）
**Q4**：WSE-3 有 90 万个 PE，连接成一个 2-D Mesh（约 949×949）。
- (a) 为什么 WSE 选 2-D Mesh 而不是 3-D Torus？给出至少 3 个原因
- (b) 2-D Mesh 在 WSE 上的**直径**是多少？平均一跳延迟（路由器 1ns + 线 0.5ns），最坏情况延迟？
- (c) 如果 WSE 想用 3-D Torus（比如 z=8 层），需要解决什么物理/制造问题？

> 答：
> (a) 三个原因：① **制造**——单芯片无法堆叠出第三维；② **时钟域**——3-D 跨 die 同步极难；③ **物理布局**——芯片是平的，第三维只能靠 TSV/混合键合，工艺成本高。
> (b) 直径 = 2×948 = 1896 跳。最坏延迟 ≈ 1896 × 1.5ns = 2.8 μs。平均跳数 ~ 949，平均延迟 ~ 1.4 μs。
> (c) 3-D Torus 需 z=8 层，每层 ~118×118。问题：① TSV 密度不足，每 PE 难有 z+ 方向端口；② 热设计功耗（TDP）散热——z 方向相邻层热耦合；③ 良率（yield）——多层堆叠良率指数下降。

**Q5**：Blue Gene/L (64k 节点) 选 3-D Torus，Intel Triton (Paragon, ~1000 节点) 选 2-D Mesh，Aurora (Intel, >1M 节点) 选 Dragonfly（拓扑的下一阶段话题）。
- (a) N=64k 时，2-D Mesh 的直径是多少？这意味着什么？
- (b) 为什么 Blue Gene/L 在 N=64k 时不能用 2-D Mesh？

> 答：
> (a) 2-D Mesh 64k = 256×256，直径 = 2×255 = 510 跳。即使每跳 10ns，最坏延迟 = 5.1 μs——对 HPC 而言太长。
> (b) 2-D Mesh 的延迟随 N 线性增长（直径 ~ 2√N），3-D Torus 直径 ~ 2∛N × 2 = 2∛N×（k/2）。N=64k 时，3-D Torus (8×8×1024? 不对) — 实际 Blue Gene/L 用 8×8×16 3-D Mesh → N=1024 不对，BG/L 是 64k 节点 = 16×8×8×8×... 重新核对：BG/L 是 64×32×32 = 65536 节点 = 2-D Torus? 不，是 3-D Torus。64×32×32 = 65536，直径 = 64+32+32 = 128 / 2 = 64 跳。**与 2-D Mesh 510 跳相比降低 8 倍**。

## 🔗 昨日回顾 → 今日衔接

**Day 5 收尾**：昨天我们看到 Ring 是"资源最少化"但"延迟最差"的极端解——直径 O(N)。

今天的"卷起来"过程：
```
Ring (1-D) ──卷→ Mesh (2-D) ──+wrap→ Torus (2-D)
              直径: O(N)  →  O(√N)        →  O(√N/2)
```

直觉：**把一维弯成二维，每跳的"进展"从 1 步变成 2 个方向上的进展，平均距离就降为原来的 1/√2**。Mesh 加 wrap-around 后，最远距离 = k/2（而不是 k-1），所以 Torus 比 Mesh 直径**再降一半**。

**Dally 的洞察**：维度-延迟-吞吐量的最优平衡点存在，公式是 **d_opt ≈ 2√N**——但物理上维度最多做到 3-D（更高维度的制造不现实）。这是 Day 7 间接网络（Clos/Fat-Tree）出场的根本原因。
