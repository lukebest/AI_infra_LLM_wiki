## 🔑 核心概念（必须掌握）

### 1. 为什么需要乱序执行？（动机回顾）

回顾 Day 9 的依赖类型：

```
指令序列：
I1: MUL  R1, R2, R3    # 慢指令，需要 10 cycles
I2: ADD  R4, R5, R6    # 与 I1 无关！但顺序执行必须等 I1 完成
I3: SUB  R7, R1, R8    # 真依赖 R1，必须等 I1

顺序执行：I1(10c) → I2(1c) → I3(1c) = 12 cycles
乱序执行：I1(开始) → I2(并行执行，1c) → ... → I3(等 I1 完成后) = ~10 cycles
```

**核心思想**：让**就绪的指令先执行**，不必等待前面未完成的指令。

### 2. Tomasulo 算法（核心中的核心！）

Tomasulo 算法的三大组件：

```
┌──────────────────────────────────────────────────┐
│                  Tomasulo 硬件结构                  │
│                                                    │
│  ┌─────────┐   ┌─────────┐   ┌─────────┐         │
│  │  保留站  │   │  保留站  │   │  保留站  │  ...    │
│  │  RS-1   │   │  RS-2   │   │  RS-3   │         │
│  └────┬────┘   └────┬────┘   └────┬────┘         │
│       │             │             │               │
│       ▼             ▼             ▼               │
│  ┌──────────────────────────────────────┐        │
│  │        公共数据总线 (CDB)              │        │
│  │   结果广播 → 所有保留站监听            │        │
│  └──────────────────────────────────────┘        │
│       │                                             │
│       ▼                                             │
│  ┌──────────────┐                                 │
│  │  寄存器组     │ ← 每个寄存器有 "Qi" 字段        │
│  │  (FP Regs)   │   指向将写它的保留站             │
│  └──────────────┘                                 │
└──────────────────────────────────────────────────┘
```

#### Tomasulo 的三个阶段：

**① Issue（发射）**
```
指令 → 检查是否有空闲保留站
  ├── 有空位 → 发射到保留站
  │     ├── 操作数就绪 → 直接取值 (Vj, Vk)
  │     └── 操作数未就绪 → 记录来源保留站号 (Qj, Qk)
  └── 无空位 → 停顿 (Structural Hazard)
```

**② Execute（执行）**
```
保留站监听 CDB：
  ├── 操作数全部就绪 → 开始执行
  └── 等待 → 持续监听 CDB，直到所需结果被广播
  
关键：不同保留站可以并行执行，只要操作数就绪！
```

**③ Write Result（写结果）**
```
执行完成 → 通过 CDB 广播结果
  ├── 所有等待此结果的保留站 → 更新操作数 (V field)
  └── 目标寄存器 → 更新值，清除 Qi 字段
```

#### 保留站 (Reservation Station) 字段：

| 字段 | 含义 |
|------|------|
| Op | 操作类型 (ADD/MUL/...) |
| Vj, Vk | 操作数的值（如果已就绪） |
| Qj, Qk | 将产生操作数的保留站号（如果未就绪） |
| Busy | 此保留站是否被占用 |
| A | 内存地址（用于 Load/Store） |

#### Tomasulo 的天才之处：

1. **隐式寄存器重命名**：保留站本身就是"虚拟寄存器"。当指令发射到保留站后，后续对同一寄存器的写不会干扰——因为操作数来源变成了保留站号，而不是寄存器号。
2. **分布式调度**：每个保留站独立监听 CDB，不需要集中的控制器。
3. **WAR/WAW 自动消除**：名称依赖通过保留站机制自动解决。

### 3. 寄存器重命名（Register Renaming）

现代处理器不再用 Tomasulo 的保留站，而是用**物理寄存器文件 (PRF)** 实现重命名：

```
逻辑寄存器 (Architectural Register, ARF)  ←  程序看到的
    ↕ 映射表 (Register Alias Table, RAT)
物理寄存器 (Physical Register, PRF)        ←  实际硬件有的

例：
逻辑: R1, R2, R3, ... R31 (32 个)
物理: P0, P1, P2, ... P127 (128 个)

RAT 映射：R1 → P5, R2 → P12, R3 → P7, ...

当指令 "MUL R1, R2, R3" 发射时：
  1. 分配新物理寄存器 Px
  2. RAT[R1] = Px（后续读 R1 的指令会指向 Px）
  3. 旧映射 P5 进入 Free List 等待回收
```

**重命名后的效果**：
```
原始代码：           重命名后：
I1: MUL R1, R2, R3   →  MUL P5, P12, P7
I2: SUB R4, R1, R5   →  SUB P8, P5, P20   (等 P5，真依赖)
I3: MUL R1, R6, R7   →  MUL P9, P15, P22  (P9≠P5！WAW 消除)
I4: ADD R5, R1, R8   →  ADD P10, P9, P25  (P10≠P20！WAR 消除)
```

→ 所有 WAR/WAW 消失，只剩 RAW（真依赖），ILP 最大化。

### 4. 重排序缓冲区 (ROB)

**问题**：乱序执行后，指令完成顺序可能与程序顺序不同 → 异常处理和精确中断变得困难。

**解决方案**：ROB

```
ROB 是一个循环队列 (FIFO)：

程序顺序 →  [I1][I2][I3][I4][I5] → 提交顺序
              ↓    ↓    ↓    ↓    ↓
           执行完成顺序可能是 I2→I1→I4→I3→I5
           
规则：只能按队头顺序提交 (Commit/Retire)
  → I2 先完成但必须等 I1 完成后才能提交
  → 保证了精确异常和顺序提交

ROB 条目字段：
  - Instruction: 指令
  - State: Issue → Execute → Write Result → Commit
  - Destination: 目标寄存器
  - Value: 计算结果
```

### 5. 完整的 OoO 流水线（现代处理器）

```
取指 (IF) → 解码 (ID) → 重命名 (RN) → 发射 (IS) → 执行 (EX) → 写回 (WB) → 提交 (CM)

     │         │           │            │           │          │          │
     ▼         ▼           ▼            ▼           ▼          ▼          ▼
   BTB/     译码+       RAT映射     Issue Queue    ALU/      CDB       ROB
   预测     类型识别    PRF分配     (等待操作数)   FPU/      广播      顺序提交
           识别依赖                              Load/
                                               Store

关键缓冲区：
  - Issue Queue（发射队列）：指令在此等待操作数就绪
  - ROB（重排序缓冲区）：保证顺序提交
  - PRF（物理寄存器文件）：重命名后的实际存储
```

## 🧪 练习题（约 30-60 分钟）

### 基础题

**Q1**：以下指令序列中，哪些可以乱序执行？哪些因真依赖必须等待？

```asm
I1: LD   R1, 0(R2)      # Load R1 from memory
I2: ADD  R3, R1, R4     # R3 = R1 + R4
I3: MUL  R5, R6, R7     # R5 = R6 * R7 (与 I1/I2 无关)
I4: SUB  R8, R5, R9     # R8 = R5 - R9
I5: ADD  R10, R3, R8    # R10 = R3 + R8
```

> **答**：
> - I1 必须先执行（无前序依赖）
> - I2 依赖 I1 (RAW on R1) → 等 I1 完成
> - I3 与 I1/I2 无关 → **可乱序执行**（与 I1 并行）
> - I4 依赖 I3 (RAW on R5) → 等 I3
> - I5 依赖 I2 (RAW on R3) 和 I4 (RAW on R8) → 等两者完成
>
> ```
> 时间轴（假设 LD=3c, ADD=1c, MUL=5c, SUB=1c）：
> 
> Cycle 1: I1(LD, 开始)        I3(MUL, 开始)
> Cycle 2:                      I3(继续)
> Cycle 3:                      I3(继续)
> Cycle 4: I1(完成→CDB)         I3(继续)
> Cycle 5: I2(ADD, 开始, 等 R1)  I3(继续)
> Cycle 6: I2(完成→CDB)          I3(完成→CDB)
> Cycle 7: I4(SUB, 开始, 等 R5)  I5 等待(需 I2✓ 和 I4)
> Cycle 8: I4(完成→CDB)
> Cycle 9: I5(ADD, 开始)
> Cycle 10: I5(完成)
> ```
> 对比顺序执行：I1(3) + I2(1) + I3(5) + I4(1) + I5(1) = 11 cycles
> 乱序执行：约 10 cycles（I3 与 I1 并行节省了 3 cycles）

### 进阶题

**Q2**：手动模拟 Tomasulo 算法

给定以下代码和硬件配置（2 个 ADD 保留站, 1 个 MUL 保留站, ADD=2c, MUL=10c）：

```asm
I1: MUL R1, R2, R3     # R1 = R2 * R3
I2: ADD R4, R1, R5     # R4 = R1 + R5 (RAW on R1)
I3: ADD R6, R7, R8     # R6 = R7 + R8 (无依赖)
I4: MUL R9, R6, R10    # R9 = R6 * R10 (RAW on R6)
```

跟踪每个周期各保留站和寄存器的状态。

> **答**（关键步骤）：
> 
> **Cycle 1 (Issue 阶段）**：
> - I1 → Issue 到 MUL1 保留站。R2、R3 就绪 → Vj=R2, Vk=R3。Q1(目标R1)=MUL1
> - I2 → Issue 到 ADD1。R1 未就绪(Qj=MUL1), R5 就绪(Vk=R5)
> - I3 → Issue 到 ADD2。R7、R8 就绪 → 开始执行
> - I4 → Issue 到 MUL1？不！MUL1 已被 I1 占用 → **结构冒险，I4 停顿**
>
> **Cycle 2**：
> - I1 在 MUL1 中执行（还需 9 cycles）
> - I3 在 ADD2 中执行（还需 1 cycle）
> - I2 等待 CDB（监听 R1=MUL1 的结果）
> - I4 等待 MUL1 空闲
>
> **Cycle 3**：
> - I3 执行完成 → CDB 广播 R6 的值
>   - I4 的 Qj 仍指向 MUL1（因为 I4 需要 MUL1 来发射，但 MUL1 被 I1 占用）
>   - 但 I4 的 R6 操作数现已就绪（从 CDB 获得）
>   - R6 寄存器更新：Qi=空, Vi=结果
>
> **Cycle 11**：
> - I1 (MUL) 执行完成 → CDB 广播 R1
>   - I2 的 Qj=MUL1 → 更新 Vj=R1 值 → 操作数齐全 → 开始执行
>   - R1 寄存器更新
>
> **Cycle 12-13**：
> - I2 在 ADD1 中执行（2 cycles）
>
> **Cycle 13**：
> - I1 完成，MUL1 释放
> - I4 可以发射到 MUL1（R6 已就绪，R10 就绪）→ 开始执行
>
> **Cycle 23**：
> - I4 (MUL) 完成 → CDB 广播 R9
>
> **总时间约 23 cycles**。顺序执行需要 10+2+2+10 = 24 cycles。看似不多，但如果代码中有更多独立指令，乱序的收益会成倍增长。

## 🔗 与 WSE/NoC/超标量研究的关联

### 今日概念 → 研究方向的映射

| 今日概念 | WSE/NoC/超标量研究关联 |
|----------|------------------------|
| Tomasulo 算法 | 现代超标量 CPU 核（Luke 研究方向）的核心机制 |
| 寄存器重命名 | 现代 CPU 使用 PRF 方案，重命名表 (RAT) 是关键瓶颈之一 |
| ROB 和顺序提交 | ROB 大小决定指令窗口大小，直接影响 IPC |
| 保留站 / 发射队列 | Issue Queue 的唤醒 (Wakeup) 和选择 (Select) 逻辑是超标量的关键瓶颈 |
| 隐式重命名消除 WAR/WAW | 为什么简单 PE（无重命名）对 AI 工作负载足够？因为 AI 代码的名称依赖极少 |

### 超标量研究的关键问题

1. **发射队列设计**：Wakeup-and-Select 逻辑是超标量的时序关键路径。如何设计低功耗、低延迟的 Issue Queue？
2. **PRF 大小 vs ROB 大小**：两者需要平衡。增大 PRF 允许更多飞行中的指令，但增加访问延迟和功耗
3. **OoO 的能效比**：OoO 硬件的面积/功耗开销巨大。对 AI 工作负载，简单阵列（如 WSE）可能更高效——这正是领域专用架构的核心论点

## 🔭 明日预告

**Day 11：分支预测 (Branch Prediction)**

今天学习了乱序执行如何解决数据冒险。但还有一类冒险——**控制冒险**（分支指令改变了执行路径）。

明天将深入：

- 🎯 **分支预测的必要性**：为什么 95% 的准确率都不够（超标量处理器每周期多条指令，分支错误预测惩罚巨大）
- 📊 **2-bit 饱和计数器**：最基础的动态预测器
- 🧠 **全局历史预测器**：GShare、TAGE——现代 CPU 如何利用全局分支历史
- 🎯 **分支目标缓冲区 (BTB)**：预测分支方向 + 目标地址

> 分支预测和乱序执行相结合，形成了现代 CPU 的**推测执行 (Speculative Execution)** 机制——在分支结果确定之前就推测性地执行后续指令。这是性能飞越的关键，也是 Spectre 漏洞的根源。
