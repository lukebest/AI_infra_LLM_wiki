## 🔑 核心概念（必须掌握）

### 1. 直连网络 vs 间接网络

```
直连网络 (Direct)               间接网络 (Indirect)
节点 = 计算+交换                节点 = 仅计算
每个节点都是路由器              交换在专门的 Switch 上

   PE ── PE                       Host ──┐
   │  ╳  │                                  ├─ Switch ── Host
   PE ── PE                       Host ──┘
   (Mesh)                          (Fat-Tree)
```

**关键区别**：
- **直连**：每个 PE 都参与路由，端口数 = 度（受限于 PE 的引脚）
- **间接**：Switch 端口数可以远超 Host 端口数（高基数 Switch）

**WSE 是直连**——90 万 PE 全部参与路由，每个 PE 4 个端口。

### 2. 五个核心度量指标

| 指标 | 符号 | 公式/定义 | 物理意义 |
|------|------|----------|----------|
| **度 (Degree)** | d | 每个节点的链路数 | 决定端口成本 |
| **直径 (Diameter)** | D | 任意两点间最短路径的**最大值** | 决定最坏延迟 |
| **平均距离 (Average Distance)** | d̄ | 所有节点对的最短路径**平均值** | 决定平均延迟 |
| **二分带宽 (Bisection Bandwidth)** | B_b | 将网络切成两半所需的**最少链路数** | 决定最大吞吐量 |
| **节点对称性** | — | 每个节点的局部结构是否相同 | 决定路由算法复杂度 |

**关键洞察**：这 5 个指标里，**二分带宽最关键**——它直接决定系统的**最大聚合吞吐量**。其他 4 个指标都可以在二分带宽允许的范围内被各种流量模式"打出来"。

### 3. 二分带宽的图示

```
4×4 Mesh 的二分切（垂直切一刀）：

  PE──PE──PE──PE
  │  │  │  │
  PE──PE──PE──PE    ← 切这一刀
  │  │  │  │
  PE──PE──PE──PE
  │  │  │  │
  PE──PE──PE──PE

穿过切割的链路数 = 4（每列一条）
所以 B_b = 4（条链路 × 链路带宽）

如果切成 Torus（环绕连接）：
  PE──PE──PE──PE─┐
  │  │  │  │    │
  PE──PE──PE──PE─┤
  │  │  │  │    │
  PE──PE──PE──PE─┤
  │  │  │  │    │
  PE──PE──PE──PE─┘
  ↑              ↑
  也有一条环绕链路穿过切割
  所以 B_b = 8（Torus = 2× Mesh）
```

**关键洞察**：Torus 的二分带宽是 Mesh 的 **2 倍**（因为环绕连接穿过切割）。这是 Torus 比 Mesh 吞吐量大的根本原因。

### 4. k-ary n-cube 的通用公式

**定义**：基数 k、维度 n 的 k-ary n-cube 有 N = kⁿ 个节点。

| 指标 | Mesh (无环绕) | Torus (有环绕) |
|------|---------------|----------------|
| 节点数 | N = kⁿ | N = kⁿ |
| 度 | 2n (内部), < 2n (边/角) | 2n (所有节点) |
| 直径 | n(k-1) | n⌊k/2⌋ |
| 平均距离 | 近似 n(2k-1)/3 - n/3k | 近似 nk/4 |
| 二分带宽 | N / k (条链路) | 2N / k (条链路) |

**关键公式（必须会推）**：
- 直径：Mesh 中最远的两个对角节点，相距 n×(k-1)
- 二分带宽：Mesh 中垂直切，N = k × kⁿ⁻¹ 个节点分成两半，每列 kⁿ⁻¹ 个节点需要穿过 kⁿ⁻¹ 条链路 → B_b = kⁿ⁻¹ = N/k

### 5. 4×4 Mesh 详算（重点！）

**参数**：N=16, k=4, n=2

| 指标 | 计算 | 结果 |
|------|------|------|
| **度 d** | 内部=4, 边=3, 角=2 | 内部=4, 边=3, 角=2 |
| **直径 D** | (0,0)→(3,3) = 3+3 = 6 | **6** |
| **平均距离 d̄** | 公式 nk/3 - n/6 ≈ 2×4/3 - 2/24 ≈ 2.58 | ≈ **2.67** |
| **二分带宽 B_b** | N/k = 16/4 = 4 条链路 | **4 条** |
| **总链路数** | 内部 2×3=6 + 边 2×3×3=18 + 角 0 → 简化 = 2×k×(k-1) = 2×4×3 = 24 | **24** |
| **节点对称性** | ❌ 不对称（角/边/内部三种节点） | 不对称 |

### 6. 4×4 Torus 详算（重点！）

**参数**：N=16, k=4, n=2

| 指标 | 计算 | 结果 |
|------|------|------|
| **度 d** | 所有节点都是 4 | **4** |
| **直径 D** | 4×⌊4/2⌋ = 4×2 = 8？不对，应是 2×⌊4/2⌋ = 2×2 = **4** | **4** |
| **平均距离 d̄** | ≈ nk/4 = 2×4/4 = **2** | **2** |
| **二分带宽 B_b** | 2×N/k = 2×4 = 8 条链路 | **8 条** |
| **总链路数** | 4×4 + 4×4 = 32（行×列） | **32** |
| **节点对称性** | ✅ 完全对称 | 对称 |

**对比总结**：
| | 4×4 Mesh | 4×4 Torus |
|--|----------|-----------|
| 度 | 内部 4, 边 3, 角 2 | 全 4 |
| 直径 | 6 | **4** (↓33%) |
| 平均距离 | ~2.67 | **2** (↓25%) |
| 二分带宽 | 4 | **8** (↑100%) |
| 总链路 | 24 | 32 (↑33%) |
| 对称 | ❌ | ✅ |

**关键洞察**：Torus 用**多 33% 的链路**换来**直径↓33%、二分带宽↑100%**。这就是为什么 Blue Gene/L 等 HPC 系统都用 Torus 而不是 Mesh——但代价是芯片的端口数和长线（环绕连接）。

## 🧪 练习题（约 45-60 分钟）

### 基础题

**Q1**：计算 8×8 Mesh 的 5 个指标。
- N = ? 度 d = ? 直径 D = ? 平均距离 d̄ ≈ ? 二分带宽 B_b = ?

> 答：N=64, 度内部=4/边=3/角=2, D = 2×7 = 14, d̄ ≈ 2×8/3 = 5.33, B_b = 64/8 = 8

**Q2**：计算 8×8 Torus 的 5 个指标，并与 Q1 的 Mesh 对比。

> 答：N=64, 度=4, D = 2×⌊8/2⌋ = 8, d̄ ≈ 2×8/4 = 4, B_b = 2×64/8 = 16
> Torus vs Mesh：直径 14→8 (↓43%)，二分带宽 8→16 (↑100%)，链路 112→128 (↑14%)

**Q3**：推导 k-ary n-cube 的**直径公式**——
- Mesh 直径 = ?
- Torus 直径 = ?

> 答：
> - Mesh 直径 = n(k-1)：最远的两个对角节点，每个维度相距 k-1，n 个维度相加
> - Torus 直径 = n⌊k/2⌋：环绕连接让每维最大距离减半（k 为偶数时正好是 k/2）

### 进阶题（与研究关联）

**Q4**：Cerebras WSE-3 有 ~900,000 PE，排列成 ~949×949 Mesh。
- 度 d = ?
- 直径 D ≈ ?
- 平均距离 d̄ ≈ ?
- 二分带宽 B_b（条链路） = ?
- 总链路数 ≈ ?

> 答：
> - 度 d = 4（边界 PE 3 个或 2 个，但内部 PE 都是 4）
> - 直径 D ≈ 2×948 = 1896
> - 平均距离 d̄ ≈ 949
> - 二分带宽 B_b = 900000/949 ≈ 949 条链路（这是关键瓶颈！）
> - 总链路 ≈ 2×949×948 ≈ 1.8M 条链路
>
> **关键洞察**：WSE 的直径是 1896 跳，意味着**任何两个 PE 的通信平均要穿过 ~500 个路由器**。这就解释了为什么 WSE 必须优化单跳延迟（亚纳秒级）和路由器微架构。

**Q5**：WSE 为什么不用 Torus（虽然 Torus 的二分带宽是 Mesh 的 2 倍）？

> 答：
> - Torus 需要**长环绕链路**——跨越整个芯片的物理长度
> - 在硅片上做长环绕线 = **巨大的 wire delay 和功耗**
> - 而 Mesh 的链路都是**局部短连线**，物理上可实现
> - 这是**物理约束 vs 拓扑指标的经典权衡**——"教科书上的最优"和"实际能造的最优"经常不一样

**Q6**：WSE 的二分带宽（~949 条链路）听起来很大，但如果 90 万 PE **同时以 1 GB/s/PE 注入流量**，总流量 = 900,000 GB/s = 900 TB/s。二分带宽是否够用？

> 答：
> - WSE 链路带宽通常 ~1 GHz × 32 bits = 4 GB/s
> - 二分带宽 = 949 条链路 × 4 GB/s ≈ 3.8 TB/s
> - 所需带宽 = 900 TB/s
> - **差 237 倍！**
> - 这说明 NoC 实际**不可能让所有 PE 同时注入满带宽**——平均注入带宽 ≪ 峰值注入带宽
> - 这就是为什么 LLM 推理要在 WSE 上做**算子融合、kernel 内通信**——减少跨 PE 的流量
