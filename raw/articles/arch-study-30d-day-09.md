### 🧭 为什么今天重要？

昨天的 5 级流水线让我们把 CPI 从多周期处理器的 ~5 降到了理想值 1。但 **CPI = 1 就够了吗？** 显然不够。现代高性能处理器每个周期可以发射和执行多条指令——这就是**超标量（Superscalar）**。

今天标志着从"每周期一条指令"到"每周期多条指令"的飞跃。这是理解 Intel、AMD、Apple Silicon 等现代高性能 CPU 核心的关键。你研究的超标量 CPU 核方向，今天正式入门。

超标量的核心挑战是**指令级并行（ILP）**：硬件能从指令流中找到多少可以同时执行的指令？这受限于程序本身的依赖结构和硬件的调度能力。

## 🔑 核心概念（必须掌握）

### 1. 指令级并行（ILP）

ILP 是指**在一个指令流中，可以并行执行的指令数量**。

```
ILP 受限于两个因素：
├── 程序本身的数据依赖和控制依赖（True Dependence）
└── 处理器硬件的资源限制（功能单元数量、寄存器端口、指令窗口大小）
```

**关键区分**：
- **真依赖 (True Dependence / RAW)**：指令 B 需要指令 A 的结果 → **必须等待**
- **名称依赖 (Name Dependence)**：指令间没有真正的数据传递，只是使用了相同的寄存器/内存地址
  - **反依赖 (Anti-dependence / WAR)**：B 读，A 先写
  - **输出依赖 (Output dependence / WAW)**：A 和 B 写同一位置
  - 名称依赖可以通过**寄存器重命名**消除（Day 10 深入）

### 2. 静态 vs 动态多发射

| 特性 | 静态多发射 (VLIW/EPIC) | 动态多发射 (Superscalar) |
|------|------------------------|--------------------------|
| 调度者 | 编译器 | 硬件 |
| 发射宽度 | 固定 | 可变 |
| 硬件复杂度 | 低 | 高 |
| 编译器复杂度 | 高 | 低 |
| 代表 | Itanium (IA-64), DSP | Intel Core, Apple M-series |
| 适合场景 | 规律的数值计算 | 通用计算、不规则代码 |

**为什么 VLIW 没能统治通用计算？**
- 无法处理动态事件（Cache miss、分支结果）
- 二进制兼容性差（不同发射宽度的代码不兼容）
- 编译器负担过重

**但 VLIW 思想在 AI 加速器中复兴**——许多 NPU 采用类 VLIW 设计，因为 AI 计算流相对规则。

### 3. CPI 的分解模型（重要量化工具）

超标量处理器的实际 CPI 可以分解为：

```
CPI_actual = CPI_ideal + CPI_stalls

CPI_stalls = CPI_data_hazard + CPI_branch_hazard + CPI_memory_hazard + CPI_resource_conflict
```

**理想 CPI**：
- 单发射流水线：CPI_ideal = 1
- 4-issue 超标量：CPI_ideal = 0.25（即 IPC = 4）

**例题**：一个 4-issue 超标量处理器，理想 IPC=4。数据冒险浪费 20% 的发射槽，分支冒险浪费 15%，Cache miss 浪费 10%。实际 IPC 是多少？

```
有效发射比例 = 1 - 0.20 - 0.15 - 0.10 = 0.55
实际 IPC = 4 × 0.55 = 2.2
```

→ **理想 IPC=4，但实际只有 2.2**。这说明冒险消除至关重要。

### 4. 机器并行度（Machine Parallelism）

```
机器并行度 = 发射宽度 × 流水线深度

但 ILP 的天花板由程序特性决定：
- 整数程序：典型 ILP ≈ 2-4
- 浮点程序：典型 ILP ≈ 4-8（更多独立计算）
- AI 推理：ILP 极高（大量独立的矩阵乘法）
```

**关键洞察**（来自 Wall 等人的经典研究）：
- 理想情况下（无限大的指令窗口、完美分支预测、完美 Cache），ILP 可以达到 10-100+
- 但实际硬件的限制让 ILP 远低于理论上限
- 这就是为什么 Day 12 会讨论"指令窗口大小的边际收益递减"

### 5. 数据依赖图（Dependency Graph）

分析 ILP 的基本工具。将程序画成有向无环图（DAG）：

```
# 示例代码
a = b + c      # I1
d = a * e      # I2 (依赖 I1: RAW on 'a')
f = g - h      # I3 (与 I1, I2 无依赖)
j = f / d      # I4 (依赖 I2: RAW on 'd'; 依赖 I3: RAW on 'f')

# 依赖图：
# I1 ──→ I2 ──→ I4
#              ↗
# I3 ──────────

# 可并行执行的分组：
# 周期1: I1, I3（无依赖，可同时发射）
# 周期2: I2（等 I1 完成）
# 周期3: I4（等 I2 和 I3 完成）
```

## 🧪 练习题（约 30-60 分钟）

### 基础题

**Q1**：识别以下代码中的所有数据依赖（RAW / WAR / WAW），假设所有变量映射到不同寄存器：

```asm
I1: ADD  R1, R2, R3    # R1 = R2 + R3
I2: SUB  R4, R1, R5    # R4 = R1 - R5
I3: MUL  R1, R6, R7    # R1 = R6 * R7
I4: ADD  R5, R1, R8    # R5 = R1 + R8
```

> **答**：
> - I1→I2：RAW (R1) — 真依赖
> - I1→I3：WAW (R1) — 输出依赖（I3 重定义 R1）
> - I2→I4：WAR (R5) — 反依赖（I4 写 R5，I2 读 R5）
> - I3→I4：RAW (R1) — 真依赖
>
> **关键**：如果用寄存器重命名，I3 的 R1 可以改名为 R9（虚拟寄存器），这样 WAW 和 WAR 都被消除，只剩 RAW 约束。

**Q2**：一个 2-issue 超标量处理器，30% 的周期因数据冒险停顿 1 槽，10% 因分支冒险完全停顿。理想 IPC=2。实际 IPC 是多少？

> **答**：
> - 70% 的周期：IPC=2（正常）
> - 20% 的周期：IPC=1（一个槽停顿：2-1=1）→ 注：30% 数据冒险中有 10% 被分支覆盖
> - 修正：更精确算法
>   - 分支冒险的周期：IPC=0（10%）
>   - 仅数据冒险的周期：IPC=1（30% - ?），这里取简单模型
>   - 假设两类冒险独立：
>   - IPC = 2 × (1-0.10) × (1-0.30) + 1 × ... （简化）
>   - 简化答案：IPC ≈ 2 × 0.9 × 0.7 = 1.26
>
> **核心启示**：即使只有 2-issue，冒险也会让实际 IPC 大幅下降。超标量发射越宽，冒险的惩罚越大（因为更多发射槽被浪费）。

### 进阶题

**Q3**：给定以下循环，分析其 ILP：

```c
for (int i = 0; i < 1000; i++) {
    a[i] = b[i] + c[i];    // S1
    d[i] = a[i] * e[i];    // S2
}
```

问题：
1. S1 和 S2 之间有什么依赖？（**答**：RAW，S2 读 S1 写的 a[i]）
2. 不同迭代之间有依赖吗？（**答**：没有！迭代 i 和 i+1 完全独立）
3. 如果展开 4 次循环，理论 IPC 是多少？

> **答**：展开后 4 个迭代可以交错执行：
> ```
> S1(0) S1(1) S1(2) S1(3)   ← 4 条独立 ADD
> S2(0) S2(1) S2(2) S2(3)   ← 4 条独立 MUL（各自等自己的 S1）
> ```
> 如果处理器有 2 个 ALU + 2 个 MUL 单元，前 4 周期执行 4×S1，后 4 周期执行 4×S2 → IPC=2。如果有足够的功能单元，前 4 周期并行 S1(0..3)，然后后 4 周期并行 S2(0..3)，实际 IPC 取决于硬件资源。

### 思考题（与 WSE/超标量研究关联）

**Q4**：Cerebras WSE 的 PE 架构非常简单（类 VLIW/数据流），没有动态超标量调度。对比现代超标量 CPU 核（如 Apple M4 的性能核，解码宽度 10，发射窗口 600+），回答：

1. WSE 选择简单 PE 的面积理由是什么？（提示：用面积预算公式 `A_total = N_pe × A_pe + A_noc + A_memory`，当 A_pe 越小，N_pe 越大）
2. 如果用超标量核替换 WSE 的 PE，单个核面积可能增大 50-100×，PE 数量相应减少——这对 LLM 推理的并行度有什么影响？
3. 为什么通用 CPU 的超标量设计对 LLM 推理效率不高？（提示：LLM 计算主要是 GEMM，ILP 极高且规律，不需要复杂的硬件动态调度）

## 🔗 与 WSE/NoC/超标量研究的关联

### 今日概念 → 研究方向的映射

| 今日概念 | WSE/NoC/超标量研究关联 |
|----------|------------------------|
| ILP 理论上限 | WSE 的 PE 虽简单，但 900K PE 提供了**海量数据并行（DLP/TLP）**，替代了 ILP |
| 静态 vs 动态调度 | WSE 的 CSL 编译器做静态调度（类 VLIW 思想），由编译器管理数据流 |
| CPI 分解模型 | 用于分析 WSE PE 的效率：PE 理想 IPC=1，但由于数据依赖和通信延迟，实际效率是多少？ |
| 数据依赖分析 | NoC 上跨 PE 的数据依赖直接影响通信开销和流水线气泡 |
| 机器并行度 | WSE 的并行度来自 PE 数量（空间并行），而不是单核 ILP |

### 超标量研究的关键问题

Luke 研究超标量 CPU 核，今天的概念为以下研究问题奠定基础：

1. **发射宽度 vs IPC 的边际收益**：从 4-issue 到 6-issue 到 8-issue，IPC 提升的代价是什么？（面积、功耗、寄存器端口数指数增长）
2. **指令窗口大小 vs ILP 开采**：更大的窗口能看到更远的并行机会，但面积和功耗代价巨大
3. **推测执行的安全网**：分支预测 + 推测执行是超标量的核心，但 Spectre 等安全漏洞揭示了新的权衡
