## 今日主题：路由基础 + 确定性路由 — 信息在拓扑上怎么走？

### 🧭 为什么今天学这个？

过去 10 天我们都在**静态**地看拓扑：节点怎么摆、链路怎么连。今天开始**动态**地看拓扑——给定一个拓扑，**报文从 A 到 B 走哪条路径**？这是"路由"问题。路由决定了：
- 延迟（路径长度）
- 吞吐量（流量分布）
- 死锁（路径是否形成环）
- 局部性利用（XY 路由 vs 自适应路由）

今天聚焦**最简单也最广泛部署**的路由范式——**确定性路由（Deterministic Routing）**，特别是 **XY 维序路由（DOR）**。它是 Mesh 上**事实标准**：WSE、Tegra、TileLink 大概率都在这一类。

## 🔑 核心概念（必须掌握）

### 1. 路由 vs 拓扑：概念分离

```
拓扑：节点和链路的物理/逻辑布局  →  静态的"骨架"
路由：决定报文走哪条路径          →  动态的"决策"
流控：链路/缓冲资源的分配机制      →  物理资源管理
```

**关键洞察**：路由是**算法**层，流控是**资源管理层**，它们解耦但强耦合。例如：
- XY 路由（算法） + 虚通道（流控层打破死锁） = Mesh 上的工业标准
- XY 路由（算法） + 单 VC Wormhole（流控层不够） = **可能死锁**

### 2. 路由算法的三大设计目标

| 目标 | 定义 | 衡量指标 |
|------|------|----------|
| **连通性 (Connectivity)** | 每对节点间是否都有路径 | 是否存在不可达节点 |
| **无死锁 (Deadlock-freedom)** | 是否会形成资源循环等待 | CDG 是否无环（明天学） |
| **自适应性 (Adaptivity)** | 能否避让拥塞/故障路径 | 可用路径数 / 总路径数 |

**附加约束**：
- **确定性 vs 自适应**
- **最小 vs 非最小**
- **单播 vs 多播**

### 3. 确定性路由 (Deterministic Routing)

**定义**：给定源 S 和目的 D，**路径完全确定**（不依赖网络状态）。

```
源 S ─── (X 方向先走) ───→ D
        路径唯一，无分支
```

**优点**：
1. **实现简单**：路由器只需看目的地址的低位/高位
2. **保序 (Order-Preserving)**：同一对源-目的的报文按序到达
3. **可预测的延迟**：便于 QoS 调度

**缺点**：
1. **不能避让拥塞**：某条路径瘫痪，就堵死
2. **负载不均**：某些方向流量集中，其他链路闲置
3. **单点故障**：链路/路由器故障 = 不可达

### 4. 维序路由 DOR (Dimension-Order Routing)

**核心思想**：**逐维降序**——在第 i 维到达目的节点之前，**绝不**进入第 i+1 维。

**2D Mesh 上的 XY 路由**：
```
路径规则：
  1. 先在 X 方向（列）调整到目的列
  2. 再在 Y 方向（行）调整到目的行
  3. 到达终点
```

**例子**：4×4 Mesh，从 (0,0) 到 (3,3)
```
X 方向走 3 步（先）:  (0,0) → (1,0) → (2,0) → (3,0)
Y 方向走 3 步（后）:  (3,0) → (3,1) → (3,2) → (3,3)

路径总长 = 3+3 = 6 跳
最短路径 ✓
确定性   ✓
```

**Y-first 的反例**：
```
从 (0,0) 到 (3,3) 走 Y-first:
  Y 方向先: (0,0) → (0,1) → (0,2) → (0,3)
  X 方向后: (0,3) → (1,3) → (2,3) → (3,3)
两种路径都合法，但 XY 和 Y-first 不能混用！
```

### 5. DOR 为什么 Mesh 上无死锁？（直觉 + 形式化）

**直觉**：XY 路由**永远把 X 方向走完再走 Y 方向**——这意味着报文**不会"反复横跳"** 同一维度。从 X 转到 Y 后，**链路使用模式**是单向推进，不会形成环。

**形式化证明（明天展开）**：
- 2D Mesh + XY + 单 VC：CDG 无环 → 无死锁（Ch.8 Dally & Seitz 定理的前提条件之一）

**关键约束**：这个**无死锁性质**依赖拓扑的**维序结构**——即每维都"前进"或"后退"，路径单调。如果绕 back（Y→X 再回到 Y），就会形成环 → 死锁。

### 6. e-cube 路由（Hypercube 上的对偶）

**Hypercube 上的 DOR**：
```
维序：先走低维（维 0），再走高维（维 1, 2, 3...）
每维上：仅在目的地址该位与当前位置不同时才走
```

**例子**：4 维 Hypercube 上，从 0000 到 1011
```
目的地址:  1 0 1 1
当前地址:  0 0 0 0
每维差异:  1 0 1 1 (第 0、2、3 维不同)
路径:      0000 → 0001 → 0011 → 0111 → 1111
            ↑维0   ↑维2   ↑维3   ↑其实逐维选择
```

**路径数 = 位差异数 = Hamming distance**(0000, 1011) = 3

**名字来源**：每个维是一条"立方体边 (cube edge)"，e-cube = "走立方体边"。

### 7. 最短路径路由 (Shortest Path Routing)

**定义**：路径长度 = hop 数，等于最短可能值。

**关键性质**：
- DOR 在 Mesh/Torus/Hypercube 上**总是最短路径**（维序对齐 + 维序单调）
- 但最短 ≠ 最优：可能不是"流量均衡"的最优

### 8. 路由算法的实现：源路由 vs 分布式

| 范式 | 实现方式 | 优点 | 缺点 |
|------|----------|------|------|
| **源路由 (Source Routing)** | 源节点把整条路径放进报文头 | 路由器极简 | 路径不能动态调整 |
| **分布式 (Distributed)** | 每跳路由器本地决策 | 灵活、可自适应 | 路由器复杂、需要死锁避免 |

**WSE 推测**：分布式确定性路由（每个 PE 路由器看目的坐标，按 XY 推进）——这是工业 NoC 的主流选择。

## 🧪 练习题（约 30-60 分钟）

### 基础题

**Q1**：在 **4×4 Mesh** 上，给定源 S 和目的 D，画出 XY 路由路径：

| 起点 | 终点 | XY 路径（按顺序列节点） | 跳数 |
|------|------|--------------------------|------|
| (0,0) | (3,3) | ? | ? |
| (1,2) | (3,0) | ? | ? |
| (2,3) | (0,1) | ? | ? |
| (0,3) | (3,0) | ? | ? |

> 答：
> - (0,0)→(3,3): (0,0)→(1,0)→(2,0)→(3,0)→(3,1)→(3,2)→(3,3)，6 跳
> - (1,2)→(3,0): (1,2)→(2,2)→(3,2)→(3,1)→(3,0)，4 跳
> - (2,3)→(0,1): (2,3)→(1,3)→(0,3)→(0,2)→(0,1)，4 跳
> - (0,3)→(3,0): (0,3)→(1,3)→(2,3)→(3,3)→(3,2)→(3,1)→(3,0)，6 跳

**Q2**：**为什么 DOR (XY) 在 Mesh 上无死锁？**（提示：通道依赖图视角——任意两条报文在使用通道时，是否会形成环？）

> 答：
> - **关键观察**：XY 路由下，每条报文**先沿 X 方向单调递增/递减**，到达目的 X 后**才进入 Y 方向**。
> - **通道依赖**：报文使用通道的顺序是**严格分层**的——先 X-通道、再 Y-通道。没有"先 Y 后 X 再回到 Y"的反向流动。
> - **CDG 无环**：依赖图是个**有向无环图 (DAG)**，因为 X-通道永远在 Y-通道"之前"。DAG 无环 → 无死锁。
> - **反例**：如果允许绕回 (任意 XY 路径)，则可能出现 (X方向前进 → Y前进 → X后退) 形成依赖环 → 死锁。

**Q3**：在 **3-D Hypercube（8 节点）** 上，从 **000** 到 **111**，e-cube 路由有几个最短路径？列出至少 3 条路径。

> 答：
> - Hamming distance H(000, 111) = 3 = 最短路径长度
> - e-cube 路由确定一条路径，但 3 位全不同 → 排列顺序由"低维优先"决定
> - 一种顺序：先维 0 再维 1 再维 2 → 000 → 001 → 011 → 111
> - 其他最短路径（不走 e-cube）：000 → 010 → 110 → 111；000 → 100 → 101 → 111；000 → 100 → 110 → 111 等共 3! = 6 条
> - 但只有 e-cube 那条是**确定性**的

### 进阶题（与研究关联）

**Q4**：Cerebras WSE-3 有约 90 万个 PE，连成 ~949×949 的 2-D Mesh。
- (a) 如果用 XY 路由，从 **左下角 PE (0,0)** 到 **右上角 PE (948, 948)** 要走多少跳？
- (b) 平均跳数是多少？
- (c) 这个延迟对 LLM 推理（典型 AllReduce 流量）影响有多大？

> 答：
> - (a) 最远距离：948 + 948 = **1896 跳**
> - (b) 平均 ~948 跳（Mesh 上均匀分布）
> - (c) 如果每跳 5ns（乐观估计）：最远 PE 间通信 = 1896 × 5 = ~10 μs
> - LLM 推理的 attention 计算是 O(seq²) 但矩阵分块后**通信模式局部化**，最长距离 PE 间通信不频繁
> - 但 **AllReduce 跨整个芯片**仍然要走 ~500-1000 跳 → ~2.5-5 μs，这是 WSE 通信瓶颈之一

**Q5**：你正在做 WSE 上的**核内同步 (In-PU synchronization)** 研究。要实现**64 个相邻 PE 的 barrier 同步**。
- (a) 假设用 XY 路由，每个 PE 通知邻居的最坏延迟是多少？
- (b) 如果改用**树形多播**（XY 路径分支），延迟能优化到几跳？
- (c) 这两种方案在 Mesh 的哪个位置延迟差异最大？（提示：中心 vs 角落）

> 答：
> - (a) 最坏延迟 = 穿越 Mesh 直径 ≈ 948 跳 × 2（来回）
> - (b) 树形多播：每条消息 O(log N) 跳 ≈ log₂(949) ≈ 10 跳；同步总延迟 = O(diameter) + O(log N) ≈ 30 跳
> - (c) 角落的 PE 离中心远，**走 XY 路径要穿越整个 Mesh**；中心的 PE 邻居都在附近
> - 优化方向：**预先建立区域性同步树**（每 8×8 子 Mesh 内独立同步，再向上传播）→ 把同步延迟从 O(diameter) 降到 O(log(diameter))

**Q6**：设计一个**NPU 核间互连**（假设 256 个 NPU 核，16×16 Mesh）。
- (a) 用 XY 路由时，NPU₀ 和 NPU₂₅₅ 之间的延迟是多少跳？
- (b) 如果流量是**点对点单播**（每个 NPU 只需通信 1-2 个邻居核），XY 路由的路径利用率高吗？为什么？
- (c) NPU 互连最需要哪种路由特性？（提示：流量特征）

> 答：
> - (a) (0,0)→(15,15) = 15+15 = **30 跳**
> - (b) 点对点单播 + XY = 高利用率（最短路径 + 无环）
> - (c) **确定性 + 保序** —— NPU 之间通信需要严格的依赖关系（同层、同 batch），保序保证数据正确性
> - WSE 类系统不需要自适应路由（流量局部化），XY 是最优选择
